**服务端也装一份 AtomChat 会得到什么、怎么配、以及什么时候该担心容量。**

## 装它有什么用

不装 → 模组是纯客户端的，图片走第三方图床（约 3 小时过期），头像各看各的皮肤。

装了之后解锁三件事：

| 能力 | 说明 |
|---|---|
| **服务端媒体托管** | 玩家发的图片 / GIF 存到你的服务器，再分发给其他玩家：内容寻址去重、按需分块下发、**只走游戏连接、不开 HTTP 端口** |
| **自定义头像同步** | 玩家上传的头像广播给同服其他装了 AtomChat 的客户端（换头像即时刷新） |
| **本服下发** | 把本服的表情包、常用语、服务器图标与 MOTD 发给进服的客户端，客户端面板里出现只读的「本服」分区 |

三者共用 `hostingEnabled` / `packEnabled` 两个总开关，可以分开关。

## 装与配

把同一个 JAR 放进服务端的 `mods/`，重启服务端。首次启动会生成 **`config/atomchat/atomchat-server.json`**（单人 / 局域网主机则是存档实例目录下的同名文件）。

### 游戏内改配置：`/atomchat gui`

OP 2 级（**单人存档无需权限**，控制台执行会提示需要回到游戏内 —— 控制台没有可绘制的界面）。这个配置屏由**执行命令的玩家的客户端**绘制，所以专用服务器、面板服、单人、局域网都能用。

- 分「服务端托管 / 本服下发」两段，单位写在标签上（KB / MB / 毫秒 / 「0 = 永久」），数值越界会**指名道姓**地拦下来；
- 保存成功后，**改配置的那个人的面板会立即刷新**（客户端会重新握手一次）；
- 其他在线玩家**下次进服**时生效；
- 两个管理员同时改不会互相覆盖：服务端用 `configVersion` 拒绝过期编辑。

> 客户端常用语里默认自带一条 `/atomchat gui`（首次生成配置时种入一次，删掉后不会再回来），方便不看文档的服主发现这个入口。

## 服务端配置全表

`config/atomchat/atomchat-server.json`：

| 键 | 默认值 | 说明 |
|---|---|---|
| `hostingEnabled` | `true` | **总开关**：本服务端是否托管聊天图片 / GIF 与玩家头像。关掉后客户端自动回退第三方图床、头像回退皮肤 |
| `maxFileKb` | `2048` | 单个托管文件的大小上限（KB），超出则客户端回退图床 |
| `maxTotalMb` | `512` | 媒体库总容量上限（MB），超出后按最旧优先删除 |
| `maxAvatarTotalMb` | `64` | 头像库总容量上限（MB），超出后按最旧优先删除 |
| `retentionDays` | `7` | 托管媒体与头像的保留天数，`0` = 永久 |
| `uploadCooldownMs` | `3000` | 同一玩家两次上传之间的最小间隔（毫秒） |
| `packEnabled` | `true` | **总开关**：是否把本服的表情 / 常用语 / 服务器标识下发给客户端 |
| `packMaxFiles` | `32` | 下发的表情文件数上限 |
| `packMaxMb` | `8` | 下发的表情总体积上限（MB） |
| `packName` | `""` | 客户端面板上显示的服名；留空则用服务器 MOTD 清洗后的首行 |
| `phrases` | `[]` | 下发给客户端的常用语（最多 20 条，每条 ≤200 字） |

数值范围会由服务端在保存时重新校验（例如表情包体积上限只能是 1–64 MB）。

## 下发内容怎么准备

| 下发什么 | 放在哪 | 备注 |
|---|---|---|
| 表情包 | 服务端 `atomchat/server/emotes/` | `png` / `jpg` / `jpeg` / `gif`；与玩家自己的 `emotes/` 目录**故意分开**，避免单机 / LAN 主机把主人收藏推给访客；专用服务器首次构建下发包时会把旧 `emotes/` 里的表情一次性拷过来（只拷不删） |
| 常用语 | 配置里的 `phrases` | ≤20 条、每条 ≤200 字 |
| 服务器图标 | 服务端根目录的 `server-icon.png` | 自动读取 |
| 服名 | `packName`，留空则取 MOTD 首行 | 会做清洗 |

传输细节：客户端先算出自己已经有哪些文件（逐文件 sha256），服务端**只补差量**，按 24 KiB 分块下发、每玩家每 tick 最多 4 块，客户端逐文件校验后整目录原子换入。**任何失败都会回一条原因写进服务端日志**。客户端硬上限是 200 个文件 / 16 MB。

## 数据落点与清理

| 路径（服务端游戏目录下） | 内容 |
|---|---|
| `config/atomchat/atomchat-server.json` | 服务端配置 |
| `atomchat/server/emotes/` | 下发给客户端的表情源 |
| `atomchat/server/media/` | 托管的聊天媒体，**文件名即内容哈希**，天然去重 |
| `atomchat/server/avatars/` | 玩家上传的头像 |

清理时机：**开服时 + 每 5 分钟 + 每次上传后**，按 `retentionDays` 与容量上限修剪最旧的条目；玩家掉线时会清掉其未完成的上传缓冲。想立刻腾空间，直接删 `media/` 或 `avatars/` 下的文件也是安全的（客户端会按需重传）。

## 排错

| 现象 | 先查 |
|---|---|
| 玩家发的图仍走图床 | 服务端是否真的加载了 AtomChat（`/atomchat gui` 能打开吗）？`hostingEnabled` 是否为 true？日志里有没有 `Stored hosted media` |
| 图发到服务端但对方看不到 | 媒体默认 7 天后会被清理；确认 `retentionDays` 与 `maxTotalMb` |
| 玩家说面板里没有「本服」分区 | 服务端 `packEnabled`；客户端 `设置 → 隐私与屏蔽 → 接收本服下发内容`；玩家是否在**配置改动前**就进服了（让他重进） |
| 服务端日志里下发失败 | 读那行原因：超过 `packMaxFiles` / `packMaxMb`、单文件过大、清单 15 秒或分块 30 秒看门狗超时 |
| 想彻底关掉托管 | `hostingEnabled=false`（客户端自动回退图床，头像回退皮肤），或直接不装服务端侧的 AtomChat |
