**两个来源、三个标签页、一条只读分界线。**

## 面板长什么样

输入栏上方点表情按钮，打开的面板有三个标签页（带滑动指示器与推入动画）：

| 标签页 | 内容 |
|---|---|
| `表情` | 内置 emoji |
| `颜文字` | 内置 kaomoji |
| `表情包` | **你自己的表情**（本地目录）+ 服务器下发的**只读「本服」分区** |

点一下即插入；如果是表情包，会先上传再插入草稿，然后自动关闭面板（一次一个）。

## 你自己的表情包

- **目录**：`.minecraft/config/atomchat/emotes/`
- **格式**：`png` / `jpg` / `jpeg` / `gif`
- **数量**：默认**不限量**；如需上限，在 `atomchat-client.json` 里把 `emoteMax` 设为正整数，重开聊天界面生效（超出后格子会滚动；从 0.2.9 起不再写死两行）
- **排序**：按文件名排序 —— 想调顺序就改文件名
- **添加**：面板末尾的 `+` 号，选一张本地图片
- **删除**：鼠标悬到缩略图上，点右上角的 `×`

> GIF 表情在**面板格子里只显示首帧**（保证滚动和格子重绘流畅），发送出去后在气泡里正常循环播放。

## 服务器下发的表情（「本服」分区）

进服时，装了 AtomChat 的服务器会把自己的表情包发给客户端。它们在表情页底部**独立的只读分区**里，带服务器图标、服名与同步状态：

- **点一下就能用**，和本地表情一样；
- **不能删、与你自己的表情分开计数**（客户端最多显示 32 个）；
- 传输是**逐文件 sha256 校验、只补差量**：你删掉一个已下发的表情，下次进服只会补那一个，不会重下整包；
- 不想接收？`设置 → 隐私与屏蔽 → 接收本服下发内容` 关掉 —— 关掉后不再向服务器请求任何内容，并立即清空已加载的视图（默认开）。

## 给服主：怎么给大家下发表情

1. 把要下发的表情文件放进**服务端**的 `config/atomchat/server-emotes/`；
2. 确认服务端配置里 `packEnabled=true`（默认开）；
3. 玩家**下次进服**时会自动同步（不需要重启服务端）。

这个目录是**故意**跟玩家自己的 `config/atomchat/emotes/` 分开的 —— 否则单机 / 局域网主机的主人会把私人收藏推给每个访客。专用服务器第一次构建下发包时，会把旧 `emotes/` 目录里已有的表情**一次性拷贝**过去（只拷贝、不删除，回滚安全）；单机 / 局域网主机**不做**这个迁移，默认也不再外推。

相关上限（都在 `config/atomchat/atomchat-server.json`，也可用 `/atomchat gui` 在游戏里改）：

| 键 | 默认 | 含义 |
|---|---|---|
| `packEnabled` | `true` | 是否把本服的表情 / 常用语 / 标识发给客户端 |
| `packMaxFiles` | `32` | 下发的表情文件数上限 |
| `packMaxMb` | `8` | 下发的表情总体积上限（MB） |
| `packName` | `""` | 客户端面板上显示的服名；留空则用服务器 MOTD 清洗后的首行 |

客户端侧另有一道硬闸：整包超过 **200 个文件 / 16 MB** 直接拒收（防止恶意服务器把客户端塞爆）。完整说明见 [服主手册](服主手册)。

## 排错

| 现象 | 原因 / 处理 |
|---|---|
| 放进目录但面板里没有 | 格式是否在 `png / jpg / jpeg / gif` 之内？是否在 `atomchat-client.json` 里设了 `emoteMax` 上限（格子会滚动，先往下滚一下）？ |
| 格子顺序不对 | 按文件名排序，改名即可 |
| 服主放了表情，玩家看不到 | 服务端 `packEnabled` 是否为 true？玩家是否关掉了「接收本服下发内容」？玩家是**进服时**同步的，让他重进一次 |
| 下发失败 | 服务端日志里会写明原因（超过 `packMaxFiles` / `packMaxMb`、单文件过大、清单超时等） |
