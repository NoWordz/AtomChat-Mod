**先按症状找，再按日志定位。** 所有排查都围绕一份日志：`.minecraft/logs/latest.log`（服务端是 `logs/latest.log`）。

## 面板打不开 / 按 T 没反应

1. **JAR 对不对**：Fabric 版只能配 Fabric Loader、NeoForge 版配 NeoForge、Forge 版配 1.20.1 + Forge 47+；装错加载器的 JAR 不会加载。也确认 Java 版本（Fabric / NeoForge 要 21+，Forge 1.20.1 要 17）。
2. **是不是被别的界面占着**：`Y` 键只在当前没有打开任何界面时才会拉起面板。
3. **看日志**：搜索 `atomchat`，有没有加载失败 / 缺少依赖（`fabric-api` 是 Fabric 版的必需项）。
4. **按键冲突**：`选项 → 控制 → 按键绑定 → AtomChat` 里确认 `打开 AtomChat`（默认 `Y`）没被别的模组抢走；原版聊天键（`T` / `/`）被其它模组改写时也可能失效。

## 文件选择窗口打不开（点图片 / 头像 / 壁纸没反应）

这是 0.2.9 修掉的一个兼容性问题：某些模组（实测触发者是 **TerraFirmaCraft / TFC**）会在非常早的阶段初始化 AWT，而 MC 客户端主类 `Main` 会把 `java.awt.headless` 设成 `true` —— 谁先碰到 AWT，这个属性就被锁死。结果是 AtomChat 弹出文件选择窗口时抛 `HeadlessException`，异常又被日志吞掉，玩家只看到「点了没反应」。

**0.2.9 起**：由 Mixin 插件在 Mixin 准备阶段（早于所有模组构造，也早于 `Main`）抢先认领 AWT。万一仍然拿不到：

- 日志里会有一条 `ERROR` 级记录，写明原因；
- 游戏内会直接弹一条提示（`atomchat.picker.headless`）。

排查时搜日志关键词：`HeadlessException`、`java.awt.headless`、`Image picker`。若你用的是 0.2.8 或更早版本，**升级到 0.2.9 即可**。

## 消息显示成灰色

灰色 = 客户端无法确定那一行是不是玩家消息，保守地当成系统消息渲染（这是**设计**，不是猜错）。常见于昵称 / 花名插件用了客户端不认识的消息格式。

缓解办法：在 `config/atomchat/atomchat-client.json` 里手写识别模板 —— `chatTemplates`（公屏）与 `whisperTemplates`（私聊），占位符支持 `{name}` `{display_name}` `{prefix}` `{suffix}` `{sep}` `{content}`（`{content}` 恰好出现一次）。改完**重开聊天界面**即生效，不用重启游戏。

## 图片相关

图片不显示、老图变破图、上传失败 → 看 [图片消息与传输路线](图片消息与传输路线)的排错表。

## 面板整块变黑（仅旧版本）

0.2.8 之前，Forge 1.20.1 上打开面板后可能整屏变黑（游戏不崩、还能打字）。根因是模糊 pre-pass 的 raw GL 状态写回与 1.20.1 的缓存门控 setter 不一致，**0.2.8 已修**；0.2.8 起若模糊 pass 出事，会退成不透明实色面板并打一条带 GL 错误码的节流警告，不再静默变黑。

## 已知不受支持

- **Linux x64**：使用文件名带 `linux-x64` 的 JAR，移除 Windows 包；Ubuntu/Debian 需安装 `libegl1 libgl1`。若面板无法启动，检查日志中的原生加载原因。
- **macOS / ARM64**：尚未打包对应原生库，面板无法启动。
- **Quark**：装了 Quark 时表情菜单不显示，正在尝试兼容。
- **其他 MC 版本 / 加载器**：目前只有 Fabric / NeoForge 1.21.1 与 Forge 1.20.1。

## Linux 上面板里的表情/颜文字变成方框（缺字体）

Linux 上面板能开、文字也正常，但表情面板的 emoji 和部分颜文字是一排空方框 —— 这不是模组坏了，是**系统里没有能画这些字符的字体**。

模组自带的 `bundled.otf` 是一份 **Noto Sans SC 子集**（约 7500 个字形），只覆盖常用汉字与日文假名，**不含 emoji、半角片假名、泰文、谚文与部分符号**。这些缺口靠**系统字体**补：Windows 自带 Segoe UI Emoji 与雅黑，所以显得正常；而精简的 Linux（含 WSL 默认镜像）常常只有 DejaVu 与 Ubuntu，于是补齐不了 —— 实测这类系统上表情面板 122 个 emoji 码位里 88 个是方框，颜文字里也有约 10 个符号（`｡ ﾉ ￢ ゛ ゜ ー ㅂ ︵ ฅ ๑`）无字可显。

装两款字体即可（Ubuntu / Debian）：

```
sudo apt install fonts-noto-cjk fonts-noto-color-emoji
fc-cache -f
```

`fonts-noto-cjk` 补汉字/假名（实测把颜文字的方框从 10 个降到 2 个），`fonts-noto-color-emoji` 补彩色 emoji（实测把 emoji 方框从 88 个降到 0）。这两个是 Ubuntu 标准仓库里的包，装完重启游戏即可。模组的字符回退会自动找到它们；不装则对应字符保持方框。

（WSL 用户注意：这不是 WSL 的锅，任何精简 Linux 都可能缺这两款字体。装完字体仍缺的少数符号——如上例中的泰文 `ฅ ๑`——属于系统里确实没有任何字体覆盖的码位，暂无法显示。）


## 开 debug，以及该把哪几行交上来

**永远有的一行**（不用开任何开关）。搜 `AtomChat build`：

```
AtomChat build 0.2.11 | Forge 47.4.10 / minecraft 1.20.1 | atomchat-Forge-1.20.1-0.2.11.jar | sha256:de20503c1a2b | git 56122d9
```

模组版本、加载器与版本、MC 版本、**真实加载到的 jar 文件名**、**这个文件内容的哈希**、构建时的提交号。
最后两项是关键：玩家经常把 jar 改名成自己喜欢的样子，名字对不上时，版本号与内容哈希仍能唯一定位到是哪一个构建。

**一整块环境摘要**（需要 `debug`）。在游戏里 `设置 → 关于` 打开调试，或手改 `config/atomchat/atomchat-client.json` 里的 `"debug": true`，重启；搜 `AtomChat environment summary`：

```
AtomChat environment summary (debug) — paste this whole block into a bug report
  build    0.2.11 | Forge 47.4.10 / minecraft 1.20.1 | git 56122d9
  artifact ...\mods\atomchat-Forge-1.20.1-0.2.11.jar | ... | loader reports 0.2.11
  runtime  Java 17.0.9 (Eclipse Adoptium) | Windows 11 10.0 | amd64
  laf      com.atom.chat.shaded.flatlaf.FlatLightLaf <- ...\mods\atomchat-....jar | ...
  skija    0.116.8 windows/x64 <- ...\skija-windows-x64-0.116.8.jar | natives loaded in 132 ms
  gpu      NVIDIA GeForce RTX 3060 | 4.6.0 NVIDIA 552.22 | NVIDIA Corporation
  switches blur=on (opacity 0.93) | wallpaper=none | imageMessages=on | animations=on | panel=440x780 @1.0x
```

它回答的正是最常被追问、又最难从日志里推出来的几件事：**这份 FlatLaf 是从哪个 jar 加载的**（旧的撞车问题就发生在这里）、**Skija 原生库到底加载成功没有**、**GPU 与驱动**、以及当时的关键开关。整块是**一条**日志记录（内部自带换行），连着复制即可，不会和别的模组插进来的日志串在一起。

`debug` 打开后还会逐条记录输入（按下什么键、输入什么字符、点到屏幕哪个点，以及那一点换算成面板坐标是哪儿）。界面是 Skia 自绘的，原版那套控件调试手段都失效，所以"这个按钮点了没反应"这类问题全靠这几行判断**点击到底有没有到达、以及落在哪个元素上**。搜 `click:`、`keyPressed:`、`charTyped:`。

## 报 bug 请带上这些

1. 上面那行 `AtomChat build`（或整块环境摘要）—— 它同时给出模组版本、加载器与 MC 版本，比手写可靠；
2. 是**单人 / 局域网主机 / 专用服务器**，服务端是否也装了 AtomChat；
3. 复现步骤（越短越好：做了什么 → 期望什么 → 实际什么）；
4. `.minecraft/logs/latest.log`（或崩溃报告 `crash-reports/`）；
5. 触发时的截图 / 录屏（界面类问题很有用）；
6. 如果和图片 / 下发有关，把日志里的 `Stored hosted media`、`Failed to upload image`、下发失败原因一并贴上。
