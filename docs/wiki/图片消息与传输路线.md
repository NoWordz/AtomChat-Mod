**发图片、收图片，以及最容易搞混的一件事：图到底存在哪。**

## 怎么发

三种方式，效果一样：

1. **点图片按钮** —— 打开一个带缩略图预览的文件选择器（默认打开系统图片文件夹 `Pictures` / `图片`）；
2. **把图片文件拖进游戏窗口** —— 直接松手即可；
3. **复制图片后按 `Ctrl+V`**。

三种方式都会先**上传**，上传期间输入框占位符显示「图片上传中…」，完成后把一段图片代码（`[[CICode,...]]`）插入草稿 —— 你还可以在发送前编辑它旁边的文字。按回车才会真正发出去。

## 图片走了哪条路

这是最常被问的问题。规则只有一条：**服务端装了 AtomChat 就优先走服务端，否则走第三方图床。**

| 路线 | 什么时候走 | 结果 |
|---|---|---|
| **服务端托管** | 服务端装了 AtomChat 且 `hostingEnabled=true` | 图片存在服务器的 `atomchat/server/media/`（文件名就是内容哈希，同一张图只存一份），消息里写的是 `atomchat-media:<id>` 短链，其他玩家按需从服务器拉取；只走游戏连接，**不开 HTTP 端口** |
| **第三方图床** | 服务端没装 AtomChat / 关了 `hostingEnabled` / 文件超过 `maxFileKb`（默认 2 MB）/ 上传失败 | 图片上传到 [uguu.se](https://uguu.se)，消息里是普通 https 链接；**链接约 3 小时后失效** |

自动回退是设计好的行为，不是故障：服务器不托管时你不会发不出图，只是图会过期。

### 怎么确认实际走了哪条

看客户端日志（`.minecraft/logs/latest.log`）里有没有这一行：

```
Stored hosted media <id> (<bytes> bytes)
```

**有** = 服务端托管成功；**没有** = 走了图床（外部图床成功时不写 info 日志，失败才有 `Failed to upload image`）。

### 服务端托管的保留策略

默认保留 **7 天**（`retentionDays`，`0` = 永久），并在开服时、每 5 分钟、以及每次上传后按容量上限修剪最旧的内容：媒体库 512 MB、头像库 64 MB。数值都在 [服主手册](服主手册)。

## 收到的图片

- 含图片代码的消息会渲染成图片气泡，按原图比例显示；**GIF 在气泡内会自动循环播放**，透明底的 PNG / GIF 直接透出面板背景。
- **右键图片 → 保存** 可以把原图存到本地（弹出的保存对话框可选路径与文件名）。
- 不想接收图片：`设置 → 聊天 → 图片消息` 关掉。关掉后**不下载、不缓存**，所有图片消息显示成绿色的 `[图片]` 占位（手动点保存仍会按需下载）。

## 缓存在哪、怎么清

| 内容 | 路径 |
|---|---|
| 下载 / 上传过的图片缓存 | `<游戏目录>/atomchat/cache/images/` |
| 服务端下发的表情、他人头像等 | `<游戏目录>/atomchat/cache/packs/`、`atomchat/server/avatars/` |
| 服务端侧的托管媒体 | `<服务端游戏目录>/atomchat/server/media/`、`avatars/` |

客户端缓存有三道自动闸：**最多 500 个文件、最多 100 MB、超过 7 天没再用过就删**（读取会刷新时间戳）。想立刻清空：`设置 → 关于 → 清除图片缓存` —— 它只清图片缓存，**不影响**表情包 / 壁纸 / 头像。

## 排错

| 现象 | 先看这里 |
|---|---|
| 图片一直显示「加载中」 | 服务端是否在跑？该图是否为服务端托管（消息里是 `atomchat-media:` 短链）而服务端已清理（默认 7 天）？ |
| 老图变空白 / 破图 | 图床链接约 3 小时过期。让服主开启服务端托管，或让对方重发 |
| 点了图片按钮没反应 / 没有窗口弹出 | 见 [常见问题排查](常见问题排查) 的「文件选择窗口打不开」 |
| 图片发不出去且日志有 `Failed to upload image` | 图床不可达（网络 / 代理）。文件大于 `maxFileKb` 时服务端不收，会直接尝试图床 |
