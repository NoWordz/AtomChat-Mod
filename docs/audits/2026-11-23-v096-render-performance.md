# 0.9.6 渲染性能调研与量测

范围：在保持现有阴影、材质、抗锯齿和动效的前提下审计 AtomChat 当前渲染路径。此处是原生组件与隐藏 OpenGL 的证据，不是完整整合包的 FPS 验收。

## 调研结论与当前实现

1. Skia `saveLayer` 分配额外表面，bounds 只是提示，不是裁剪。因此只对真实需要的混合、阴影和 AA 裁切保留图层，不能把所有 layer 当成可直接删除的开销。当前图片局部覆盖与透明叠层依赖这些层，未为性能而移除。
2. Skia 与 Minecraft 共用 GL 时，`flushAndSubmit` 以及外部 GL 状态恢复有顺序契约。单看函数调用次数不能决定删除同步。本轮未修改 AtomLib 或取消生产桥的必要提交。
3. 静止内容适合复用既有布局、字形和 HUD 图像缓存；动态内容必须参与失效。现有 HUD 缓存已经覆盖静止文字和名字，本轮没有重启历史 CPU/GPU 全量缓存试验。新增混淆文字按等宽字形槽绘制，复用单字形缓存，并绕过整行静止图像缓存，避免文字冻结或每帧生成全新随机长串占满字形缓存。
4. 每条富文本的测量、截断、选区与绘制使用同一套字体选择；复用测量器而不在每个 span 的热路径里重复生成捕获字体的回调。粗体采用既有缓存字重，不每帧创建字体。

权威依据：[Skia Canvas](https://api.skia.org/classSkCanvas.html)、[Skia GPU DirectContext](https://api.skia.org/classGrDirectContext.html)。

## 实验一：直接调用已有纯色填充 API

候选把气泡的通用 Paint 检查改为直接调用已有纯色填充。48 种样式/分组/方向/透明度组合的输出逐字节相同，但原生光栅配对耗时没有稳定收益，后半段两条路径都受运行时波动影响，稳态 JVM 分配也同为 376 字节/次。

结论：未接入生产，不用降低测试门槛或更换场景把它包装为优化。原始输出在 `build/v096/performance/solid-fill.csv`，测试 `BubbleFillCostTest`。

## 实验二：复用文字装饰线画笔

原实现每画一条下划线都构造、配置并关闭一个 Skija Paint。新实现复用渲染线程专用画笔，每次明确设置颜色和线宽；删除线复用同一原语。沿用已有的线位、厚度与 AA 参数。

- 六组 1×/1.25×/2×、不透明/半透明输出与旧实现逐字节一致。
- 同一 JVM、相同字体与表面，预热后八段 ABBA 配对、每段 6000 条线。
- 旧实现每条线 JVM 分配中位数 120 字节，新实现 0 字节。
- 本轮旧实现耗时中位数约 990 ns/条，新实现约 866 ns/条；单段有反向波动，不能外推为游戏 FPS 百分比。

结论：保留复用画笔的改动，直接证据支持减少渲染线程分配并保持装饰线观感。原始输出 `build/v096/performance/text-decoration.csv`，行为与像素对照在 `TextDecorationCostTest`。三端后续全量测试的同名量测按目标写入子目录，不能混为同一配对实验。

## 圆弧与图片的 GPU 核对

`ChatBubbleGpuTest` 在真实隐藏 OpenGL 上以 16 倍原生圆弧采样为参考，覆盖四种分组、两个方向、两个分数像素相位，共 16 个场景。最大边缘 alpha MAE 为 0.7921，沿用既有小于 3 的要求；同场景不透明图片裁切和纯色气泡 alpha 最大差为 0。这里证明轮廓及图片接线，不能代替完整游戏的材质、HUD 模组组合和帧时验收。

原始记录：`build/v096/gpu/1.21.1-fabric/circular-bubbles.csv`，命令记录 `build/v096/gpu-format-verification.log`。

## 当前限制

字体兼容整合后的独审另发现每帧扫描全部聊天历史的回退，已改为面板可见行与 HUD 实际可见／退场行预准备。字体路由按文本复用，storage 查找、码点元数据、拥有的 raster 分开设有界缓存；隐藏行的测量不上传图像，混淆相位、重载和图像淘汰后仍在本帧 prepare。真实 provider 回归验证普通文字预热后重复测量不再查原生 storage，并验证两个批次未知字体 ID 不持续扩大 storage 缓存。这些证据针对具体调用链和生命周期，不作为整体游戏帧时结论。

本轮没有启动完整游戏或进行整合包帧时 A/B，没有降低 AA、模糊、阴影或动画，也没有修改配套 AtomLib。必要三端全量测试、正式既有契约和独立审查的最终状态另记于本轮验证记录。
