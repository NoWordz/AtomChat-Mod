# AtomChat 0.9.3 性能与渲染审计

源码基线为 e55deed8。发布标签 v0.9.2 相对该提交只差发布状态文档。当前验证在 Windows x64、Fabric 1.21.1 和 RTX 5060 Laptop GPU 上进行。实机使用从 CCB 取出的启动器环境与复制存档，启用 Fabric API、AtomChat、AtomLib 和测量模组。整帧数据、隐藏 OpenGL 和软件光栅分别报告。

## 核对结果

## 量化记录

- 既有 0.9.2 路线和数据见 [切页实测](../verification/2026-11-19-v092-navigation-frame-times.md) 与 [功能验证](../verification/2026-11-19-v092-functional-verification.md)。候选与 CCB 发布验收使用的包身份不同。
- 本轮 Fabric 隐藏 GL 在 2560 × 1600 绘制热态表情面板，p50 为 0.612 ms，p95 为 0.884 ms。软件光栅的同项为 0.842 和 1.035 ms。窗口、模组组合和实际世界负载不在这组探针内。
- 本轮 Fabric 隐藏 GL 的五段 Kawase 着色器在 480 × 860、900 × 1500、1440 × 2160 下 p50 为 0.0625、0.1792、0.3935 ms。数值只覆盖五段 shader，未包含截图纹理、补边、布局、Skija 合成及游戏帧。
- 原生释放的探针先以旧实现观测到第一次重载后 program 仍存活，再用修正实现跑过 20 次重载。探针用实际 ShaderProgram 与发布资源，测试入口直接调资源重载回调所用的方法。
- 发布的 0.9.2 配 0.7.0 进入存档，但打开面板在 SettingsContractResources 的初始化处报告 INCOMPATIBLE_PROFILE，得到 0 圈。本轮对这个组合只保留启动记录，两套有效组合的对照包含库和应用代码的共同变化。
- 0.9.3 本地开发包在匹配的 0.7.0 上使用项目现有的开发构建路径。按 0.9.2 已审定 Git 版本重跑 Fabric 的严格源码检查，得到 INVALID_REUSED_VERSION。已在临时目录编译三端的设置设计版本 2 草案，核对配方、资源和布局字段与原版本一致。正式配套还需用现有检查流程完成新的源码证据、原生画面与独立审定。
- WSL Ubuntu 24.04 x86_64 上，用公开 Fabric AtomLib 0.7.0 的 JVM 探针实测 Skija 和 Yoga 空缓存下载、离线重启、软件光栅和布局。AtomChat 0.9.3 游戏内的平台验收范围为 Windows。

## 构建与复核

- 11 月 20 日，Fabric 和 Forge 在关闭模组时的预热判断补丁之前，分别执行全量 test build 和 AtomLib 输入校验，共 2210 项含 16 跳过、2193 项含 16 跳过，零失败。NeoForge 先执行全量 test build 通过，再针对头栏、服务端 GUI 和相关预热分批复测，末次相关行为组 32 项全通过。
- 最终三个包均跑 12 项字形、预热及缓存专项，零失败和跳过，assemble、依赖输入、JAR、资源和版本校验通过。历史截图由测试自动生成的 30 处差异已从独立工作树定向还原，生成副本另存在本轮 build 目录。
- 独审确认了 Fabric 版本下限、恢复按钮属于实际绘制的分区，以及窄头栏为时钟保留空间的问题，均已修正复核。模组关闭时不执行新增的 Emoji 预热。高密度回退、贴纸首滚和候选自身首次开面板仍在已知范围。
- 开发构建按 README 跳过原有正式契约任务。另用已审定 0.9.2 Git 输入执行严格 Fabric 源码检查，状态为 INVALID_REUSED_VERSION。三端设置设计版本 2 草案编译通过且除身份和构建绑定外的设计字段与版本 1 一致。尚未获得新版原生画面与独立审定。

## CCB 验收后的收尾

- 卡片与面板采用五次 Kawase 采样，偏移以设备像素定义。卡片缓冲在半分辨率运行，按缓冲尺寸换算偏移。卡片强度不超过面板时沿用面板的模糊，超过时可见卡片共用一份结果。世界背景以面板内缘裁切后夹取边缘像素，壁纸继续按原位置采样。
- 900 × 1500 的隐藏 OpenGL 样本在同一块 RTX 5060 Laptop GPU 上交替执行高斯对照和 Kawase 卡片链路。以采样核的每轴方差匹配两边的模糊范围，包含取得离屏场景快照、创建半尺寸缓冲、滤波、六处圆角裁剪与合成，以及同步等待。预热 30 次后各采 90 次，高斯 p50／p95 为 0.494／0.861 ms，Kawase 为 0.508／0.833 ms。本组结果用于比较实现成本，未包含游戏世界渲染、原版 framebuffer 取图或实际 CCB 帧时。
- 系统、引用、时间分隔和图片占位的胶囊共用 85% 的最低底色不透明度。HUD 复用引用的富文本信息、色彩与单行省略。在视口空间不足时保留原版 HUD 兜底。定向原生像素用例检查引用着色、透明底色和世界裁切。
- Windows x64 系统选择器通过独立 GLFW 父窗口探针。中文标题的打开、另存为窗口均可见，Win32 返回的拥有者与 GLFW 窗口一致，取消后不进入兼容选择器。完整 CCB 真全屏、实际文件选定和焦点恢复属于玩家验收。FlatLaf 兼容选择器仍保留图像缩略图和文件过滤。
- 设置契约候选设计版本 2 使用 AtomLib 0.7.0，与原 profile 接口兼容。用提交审定前的工作树构建采集历史设置和服务端托管，共 420 个场景样本，对比基准的像素、观察值、状态和声音事件一致。候选复用原参考文件，正式构建需要已审定的源码引用。
- 最终 `test build verifyAtomLibInput` 开发构建中 Fabric 2213 项（跳过 14），Forge 和 NeoForge 各 2196 项（各跳过 16），零失败。Fabric 额外开启隐藏 GL 模糊相关回归。前序失败包括旧致谢行数及卡片视口假设、模糊参数移位后的源码断言、贴边测试的边框夹具，以及 Windows 输出文件占用。调整夹具和断言后，完整三端运行成功。测试重绘的 30 张历史图归档到 `build/v093/regenerated-closeout-captures.zip`，仓库历史图恢复为测试前字节。

## 聊天 HUD 阴影与游戏坐标

- CCB 的 Ok Zoomer 10.0.0-beta.10 在 HUD 外层应用缩放和平移。旧聊天视口只允许平移，快捷图标从独立窗口尺寸推导位置。现在两者都读取 HUD pose。缩放作用于排版结束后的绘制，光栅密度保持稳定。Forge 聊天位置事件的纯平移仍限制在屏幕边界内。
- `ChatHudTest.measureIdleHudRasterPaint` 用同一组 10 条静态消息、同一 CPU 光栅画布运行三轮，每轮预热 600 次并采 1200 帧。三轮中位的 p50／p95 从 0.9082／1.5728 ms 变为 0.6680／0.8143 ms。新实现另重建 HUD 行与外轮廓阴影缓存 40 次，首帧 p50／p95 为 5.0868／6.2602 ms。此处计量聊天绘制 CPU 墙钟时间，完整游戏帧时和 GPU 开销留待实机复测。
- `build/v093/hud-shadows/preview.png` 为离屏亮暗背景样本，含头像占位、名字、系统和引用胶囊、图像及文字气泡。自动验证缩放后的快捷键和聊天位置、GIF 帧变化、透明轮廓内部及淡出。

## HUD 媒体和面板列表复测

17:16 CCB 包 `b4a56a0f…` 对应的修改前源码和新版共用 Fabric 离屏夹具。画布 1280 × 1440，GUI 密度 3，聊天不透明度 230/255，静态聊天、不同静态缩略图、三帧 GIF 的多个实例各一组。每组热态跑三轮，每轮预热 240 次、取样 300 次，表中为三轮各分位数的中位。冷态 30 次，逐次重建 HUD 布局缓存、静态行与标题、阴影轮廓补片，字体、输入媒体和驱动进程继续热用。每次清空目标在计时之外。新版本相同组交替开关阴影，始终关闭入场动效，无面板模糊。

3 倍 GUI 缩放时，较宽文字行超过旧的单行位图上限，退回逐帧绘制名字滤镜。旧图片标题的软影在 CPU 光栅化后才提交给 Skia，需要新建位图和上传。新版允许更宽的行并以字节预算逐条淘汰，缩小标题位图及半透明合成范围，静态 HUD 笔画直接在现有 Skija GL 上下文生成。上下文、像素密度或性能模式变化后重建可见缓存。头像和真实图片继续单独绘制，动画图片沿用解码及取帧逻辑。现有 HUD、快捷提示／通知仍有各自的渲染桥入口，本次计时未覆盖桥接 GL 状态、游戏世界、皮肤取图和 Iris 等整合包负载。

面板消息沿用原视口裁切和消息命中。绘制从已测行尾二分定位，已在入场中的行保留原清理行为。缓存边缘软影和名字掩码，真实图及 GIF 的透明区仍显示背景。反应与加载更早按钮的阴影随当前胶囊变换，重复标签采用同族文字背衬，返回底部沿用原浮面。220 条文字和图片混合的离屏滚动，每帧扩展视口最多走 8 行。软件光栅 p50／p95 为标准 2.115／2.988 ms，性能模式 0.323／0.583 ms，计量范围为消息列表。

性能模式位于「关于」的调试折叠组。JSON 仅增加布尔开关，关闭时读回用户已有强度和动效。开启时面板、卡片、通知与 HUD 均跳过模糊或软影，禁用相关控件及装饰动效，保留硬背衬、消息操作及 GIF 播放。测试覆盖旧 JSON、跨重启、预设与重置的锁定、避免访问 GL 捕获入口、原生像素开关前后消除及恢复阴影。

### 透明图片

面板和 HUD 从同一个图片缓存读取透明标记。静态图片按最长边 768 的实际显示位图检测，检查发生在加载线程。Codec 证明不透明的文件沿用原解码路径。缓存继续写显示尺寸 WebP 或 PNG。4096 × 64 源图仅带一处透明像素的回归用例确认，缩小为 768 × 12 后按不透明图绘制，磁盘重载仍得到同样结果。

GIF 在解码时检查可播放帧的 CPU 位图，首个带透明像素的帧决定整段动画和 HUD 缩略图共用的标记。用例特意让第一帧完全不透明、后续帧出现透明，两个画面都没有图片外框影。面板、HUD 的名字、头像、引用和加载占位走原路径。透明 PNG 与不透明 PNG/JPEG 的检测覆盖了误导性扩展名、静态缓存重载与动画帧缓存。亮暗面板预览及 HUD 并排预览保存在 `build/v093/performance-mode/`。
