# AtomChat 0.9.2 切页实机复测

2026-11-19 19:24–19:30，Windows 隔离单机，Minecraft 1.21.1、Fabric Loader 0.17.3、Fabric API、AtomLib 0.6.0 和实际候选包。i7-14650HX，OpenGL 驱动报告 RTX 5060 Laptop GPU。窗口启动参数 1600 × 900，GUI 缩放 3、渲染距离 8、帧率上限 240、垂直同步关闭。切页样式为滑动，面板背景模糊在两档都保持 300%。各进程使用同一份存档副本和相同位置。隔离存档补齐了原版下界和末地定义，实际采样始终在主世界。

## 测法

- 按「聊天 → 设置首页 → 外观设置 → 返回设置首页」运行，每圈重新点聊天页签。探针走真实鼠标点击处理并核对目标页面，步骤间隔约 950 ms。
- 候选按 0% → 300% → 300% → 0% 顺序启动四个独立进程，每个进程跑 12 圈并记录运行时实际卡片模糊值。随后在同一存档上用原 CCB 安装包的副本跑 0.9.1 基线 12 圈。
- 探针记录相邻游戏渲染入口之间的帧时间。点击首帧从进入点击处理前开始计时。切页取点击后 0–319 ms，热切页合并第 2–12 圈的三段，稳态取这三段点击后 650–899 ms。60 FPS 帧预算为 16.67 ms。
- 候选 JAR 为 0.9.2，构建标记 `97a108c+dirty`，SHA-256 前缀 `86536b9370b7`。0.9.1 基线为 `b84c296+dirty`，包哈希前缀 `b29945efefb2`。前后沿用同一个 AtomLib 已发布 Maven 输入。

## 结果

| 包与配置 | 首次进外观首帧 | 首次外观超过 16.67 ms 的帧数 | 热切 p95 / p99 | 热切超过 16.67 ms 的帧数 | 稳态 p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0.9.1 基线 | 25.05 ms | 1 | 9.58 / 10.89 ms | 1 | 5.42 ms |
| 0.9.2 卡片模糊 0%，第 1 轮 | 18.43 ms | 1 | 10.36 / 11.82 ms | 0 | 6.53 ms |
| 0.9.2 卡片模糊 0%，第 2 轮 | 18.18 ms | 1 | 9.76 / 11.16 ms | 1 | 5.61 ms |
| 0.9.2 卡片模糊 300%，第 1 轮 | 23.17 ms | 2 | 10.56 / 11.83 ms | 1 | 6.18 ms |
| 0.9.2 卡片模糊 300%，第 2 轮 | 20.33 ms | 1 | 10.89 / 12.79 ms | 3 | 6.32 ms |

- 四轮的首次外观峰值都在点击首帧。两档都仍有首入长帧，300% 第一轮还有一帧 21.37 ms。候选未复现预热前候选在该处测得的 30.26 和 33.13 ms，亦低于本次同存档基线的 25.05 ms。
- 热切 p95 为 9.76–10.36 ms（0%）和 10.56–10.89 ms（300%）。本次基线为 9.58 ms，样本尚不足以证明热切有稳定收益。四轮候选的热切最慢帧为 26.78 ms，稳态样本均未超过 16.67 ms。
- 结果适用于隔离 Fabric 客户端和约 950 ms 的操作间隔。完整 CCB 模组组合、Forge、NeoForge 和更快的连点未在本轮做整帧采样。

原始帧表和日志位于 `build/v092-route/matched_*/frames.csv` 与对应的 `launcher.log`。各阶段分位数和最慢帧位置见 `build/v092-route/final-summary.json`。复跑入口为同目录的 `launch.py`，测试探针为 `Route.java`，统计脚本为 `route_metrics.py`。

## 首次外观页追踪

在同一 Fabric 环境，对修复前候选另外开启方法计时。每档独立启动，采集首次和第二次切页。以下数据仅用于定位。

| 卡片模糊 | 首帧总时间 | 点击处理 | 外观页布局 | 行绘制准备 |
| --- | ---: | ---: | ---: | ---: |
| 0% | 18.28 ms | 0.22 ms | 1.22 ms | 9.50 ms |
| 300% | 22.55 ms | 0.22 ms | 1.43 ms | 10.86 ms |

首次进入时，页面记录器会调用外观页绘制。此时若干行和合并卡片仍在错峰入场的等待期，透明度为 0。旧路径照常录制它们的阴影、内容和预览，第二帧的行绘制准备已回落到 0.30 ms 和 0.55 ms。方法时间包含子调用，诊断原始数据位于 `build/v092-route/cold_spans_*/trace.csv`。

外观页现在在记录布局和命中变换后，跳过透明度为 0 的卡片及单行绘制。回归用例固定动画时间，修复前在全透明帧观察到两次预览绘制，修复后为零，并核对滑动命中变换及两条预览进入可见阶段后的绘制。

只跳过透明绘制的候选在 0% 和 300% 的四次新进程采样中，首帧均低于 16.67 ms，仍在点击后的 25–34 ms 处各出现一帧 17.85–20.40 ms。对 300% 增加逐行计时后，尖峰对应主题预览第一次可见。该帧行绘制为 5.62 ms，主题预览占 3.31 ms。

设置首页的行文本预备现在用一次独立预览条带和临时绘图记录器准备主题预览。记录器在同一帧释放，整份记录无 GPU 回放。开发阶段的诊断记录中，预备花了 3.97 ms，主题预览的首个可见帧绘制降至 0.23 ms。行高测量和主题准备分别记录完成状态，直接返回设置首页也能补做预备。透明帧仍推进条带的滚动，保留按下和松手选择的实际预设。

两处交互回归均先复现失败再修复。透明壁纸条带滚动一格后，应选中第二张壁纸。外观页只完成行高测量便离开时，设置首页仍应完成一次预览准备。诊断详细记录在 `build/v092-route/fixed_detail_300/` 和 `build/v092-route/fixed_warm_detail_300/`。
