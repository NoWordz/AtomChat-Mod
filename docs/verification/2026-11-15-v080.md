# 0.8.0 消息反应与 UI 修订

本文保留 13:23 的候选记录。15:25 的实机反馈候选已精确撤销公共限宽并更新开合/HUD，见[后续验证与部署](2026-11-15-v080-followup.md)。以下原始范围及计数不冒充后续结果。

## 实现范围

- 反应以服务端投递编号绑定消息，文本指纹只校验投递；v2 可选频道要求两端升级，旧服务端保留原有本地回显。
- 原版系统广播按调用分配编号，私聊按每个目标配对编号；投递作用域在异常、取消和嵌套发送后恢复，反应只发给该消息的接收者。
- 客户端在原版延迟队列之前取走投递令牌，并随实际回调传递；反应同步启用时等待权威回声，独立消息不再被防刷合并成一个身份。
- Toast 为软阴影预留边界，长文本按可用宽高排版；极长反馈保留省略标记。返回底部按钮使用同源绘制/命中几何，并复用菜单的面内明暗和上沿高亮。
- 宽面板的栏位和内容列居中限宽，设置首页保留 2×2 方卡并限制最大边长。
- 调整低对比的预设文字/气泡配色；玻璃预设卡片使用默认透明度。已保存的自定义颜色保持，重选预设可应用新版材质。
- HUD 使用纯白填充气泡和三个透明镂空点，实际键名、字号和边距随原版 GUI scale；面板密度不影响 HUD，F1/其他屏幕隐藏，面板开合共用互补进度。
- HUD 图标与键名使用柔和黑色投影，图标投影只在完整外轮廓之外绘制，三个孔仍透明。
- 设置 tab 栏从内容快照分离，始终由固定 chrome 层绘制；输入坐标在该区域也不经过内容缩放/滑动反变换。

## 范围限制

- 新网络 Mixin 尚未在真实专服、多人联机或混合端插件环境加载验证。
- 原版消息、原版系统广播、原版私聊已有接线；第三方自行循环发送且绕开标准广播入口时，需要由其接入共用投递编号，不能凭同文或时间窗口猜测身份。
- 原版 GUI 缩放、F1、开合中断、IME 和整合包观感仍需实机复测。
- 不重录视觉基线，不建立 SHA/trust/hook/只读锁；部署时仅核对候选、安装与备份产物。
