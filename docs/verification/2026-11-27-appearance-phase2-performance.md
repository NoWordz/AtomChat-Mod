# 外观 API 第二阶段的性能排查

2026-11-27 用已归档的 Fabric 1.21.1 分发包对照 `8b62bf95` 和阶段一 `a8b2ec4c`。两版首次进入聊天历史均出现明显长帧，尖峰集中在输入后的面板绘制。两次旧包热切结果覆盖了阶段一混搭选择的热切结果。当前回放没有复现混搭导致外观页签持续卡顿。补测捕获一次壁纸选择迟滞和几次公屏附近的长帧，证据不足以定位到可修复的单个回归点。

## 环境与输入

- Windows 私有桌面，独立游戏目录，历史 CCB 夹具、1600×900、均衡档、原有 GUI 缩放和 160 行聊天数据。保持同一个平坦世界和 Iris Bliss 低配光影。JDK 21.0.8、RTX 5060 Laptop、OpenGL 4.6 NVIDIA 617.42。各轮串行，使用生产渲染入口与 debug 分段。系统和驱动状态在各轮仍有波动。
- 旧包的 SHA-256 为 `678fa661f71c2fb3a38fd344fda5db9bf6f66151290c6af01978e92d3e4687ef`。阶段一包的 SHA-256 为 `ff122fc65931926e6981ac2539c4b2b5cb772faef341c2b577eb66cc987d0e20`。两者都和各自构建回执一致。共用 Fabric AtomLib 0.7.1，SHA-256 为 `7351adebd4d12f11ab1bcac253aafe4abd44c50d74a6df3e9a9a56286d965308`。
- 装附属的两轮使用第一阶段归档的 Harbor 和 Signal Fabric 示例。混搭轮预写 `atomchat_signal:capsule`、`atomchat_harbor:chamfer`、`atomchat_harbor:tide_ring` 和 `atomchat_harbor:moonlit_harbor`。另一轮保留四个内置选项。阶段一在设置中持久化和展示选择，四类部件的绘制接线属于后续阶段。
- 扩展 `tools/run_v098_perf_replay.py` 的隔离驱动。进入世界后留 12 秒预热，再记录 12 秒无面板控制组。每轮冷开设置，随后走 18 个相同动作。外观与聊天设置的页签从游戏鼠标按下与松开路径操作，首页、详情和公屏切换走生产导航入口并断言目标。末尾再记录 12 秒关面板控制组。JFR 以动作时间和 frame ID 配对游戏循环、面板 CPU 墙钟、GL 查询与 `PanelSegments`。
- 历史原驱动的基线校准先独立跑通。扩展驱动曾因方法可见性编译失败，随后因原驱动要求整段都停在设置详情页而在进入聊天根页时被拒绝。修正的是隔离探针，最终表格仅使用完整结束的五轮。测试进程只启动夹具目录，用户游戏实例未被操作。

## 跨版本串行对照

下表均为毫秒。三项首次切换是动作后的首个游戏循环间隔。热切四次，统计每个动作之后 320 ms 内的 p95，再取四次 p95 的中位数。无面板列取控制组末尾 6 秒的 p95。CPU 和 GPU 各自覆盖一段范围，GL 查询也可能包含等待，不能相加。

| 顺序与配置 | 无面板 | 首次关于 | 首次聊天历史 | 切入公屏 | 热切循环 | 热切 CPU | 热切 GPU |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 1. 旧包 | 10.73 | 64.98 | 89.31 | 19.98 | 9.78 | 5.33 | 4.60 |
| 2. 阶段一混搭选中 | 6.64 | 39.94 | 79.85 | 22.95 | 13.68 | 6.78 | 6.03 |
| 3. 阶段一装附属、用内置 | 13.95 | 49.11 | 94.67 | 21.65 | 19.35 | 9.66 | 10.28 |
| 4. 阶段一裸包 | 13.88 | 52.72 | 112.55 | 23.82 | 16.49 | 9.00 | 8.95 |
| 5. 旧包复测 | 10.83 | 63.53 | 105.19 | 16.33 | 18.22 | 10.01 | 10.05 |

- 首次聊天历史的动作回调耗时为 0.52–0.89 ms。对应开头绘制长帧的 `DRAW` 区间为 72.44–99.35 ms，`BRIDGE_EXIT` 的窗口峰值为 2.65–4.46 ms。五轮动作后 320 ms 内均无 GC 事件。这把可复现尖峰定位到输入返回后的页面绘制。采样粒度不足以确认绘制中哪一个调用独占主要耗时。
- 首次切到外观材质时，两个旧包样本的首个循环间隔为 43.40、34.11 ms。阶段一混搭和装附属用内置分别为 45.65、46.65 ms。阶段一裸包有一次 140.05 ms 尖峰，其中动作回调为 6.37 ms。这次尖峰没有在另外两轮阶段一中出现。冷开第一张面板帧的 CPU 为 165.73–268.78 ms，屏幕构造中的配置重载为 13.25–20.98 ms。冷开场景还包含夹具数据准备，所以单列 CPU 首帧，不把场景入口到首帧的间隔当作玩家点击延迟。
- 旧包两轮热切的循环 p95 为 9.78 和 18.22 ms，无面板控制组 p95 接近。阶段一装附属、仍用内置的一轮比已选混搭更慢，关面板时也更慢。现有数据不能把单轮的几毫秒差异归因于附属选择。仍缺用户发生卡顿时的页面、操作和配置。

## 同进程选择回放

用相同阶段一 JAR 和两个附属，在隔离目录放入之前归档的 250,002 字节静态壁纸。先通过鼠标控件各切四次气泡、面板轮廓、头像框和动态壁纸，共 16 次，逐次验证选中 ID 变化。首次从静态切到动态也验证旧静态文件已移除，最后读回保存的客户端配置。以下是单轮样本，单位为毫秒。

| 控件 | 首次回调 | 首次循环 | 热切回调最大值 | 热切循环最大值 |
| --- | ---: | ---: | ---: | ---: |
| 气泡 | 11.43 | 24.71 | 10.45 | 18.26 |
| 面板轮廓 | 8.63 | 16.44 | 8.79 | 17.40 |
| 头像框 | 8.46 | 16.25 | 10.69 | 19.14 |
| 动态壁纸 | 20.99 | 39.81 | 12.50 | 20.56 |

真实选择回调包含同步保存。首次动态壁纸操作还经过静态文件替换事务，录到一次约 40 ms 的循环间隔。JFR 没记录到回调窗口内单次至少 1 ms 的 Java 文件读写事件，该采样未覆盖所有路径检查和文件移动。这一例只能定位到整个输入回调与随后帧，尚不能归因到事务中的某一步。

之后保持客户端和附属不变，仅在每组开始时设置四项选择，在组内执行真实页签点击与生产页面切换。默认、混搭、混搭、默认各 12 次动作。每组包含 6 次外观材质／主题热切及 6 次设置、聊天列表、公屏和返回导航。热切栏是组内六次动作窗口 p95 的中位数，公屏栏是各组一次公屏切入后 320 ms 的 p95。

| 同进程顺序 | 外观热切循环 | 外观热切 CPU | 外观热切 GPU | 切入公屏循环 p95 |
| --- | ---: | ---: | ---: | ---: |
| 默认 1 | 16.27 | 8.95 | 8.82 | 26.59 |
| 混搭 1 | 14.29 | 7.21 | 6.69 | 34.02 |
| 混搭 2 | 13.39 | 6.71 | 6.45 | 46.19 |
| 默认 2 | 16.00 | 7.08 | 6.90 | 21.47 |

外观页签热切没有出现混搭变慢。两段混搭窗口里的公屏切入 p95 较高，第二段聊天列表还出现 74.98 ms 的循环帧。各公屏窗口只有 9–17 帧。首帧、后续游戏循环及面板区间同向程度不同，聊天列表尖峰所在窗口的模糊墙钟也升高。阶段一的公屏渲染入口尚未使用附属选择，现有分段和栈样本没有给出从选择到这些尖峰的调用链。保留这组差异供有具体复现路径时对照。


## 验证范围

这次跨版本回放覆盖 Windows Fabric 的真实输入、导航与渲染。两个输入包各自归档的 Fabric、NeoForge、Forge 构建回执均为零失败、各 196 个原生场景通过。阶段一回执中的常规测试跳过数分别为 21、19、19。本次复核了回执和输入摘要，原生场景是已有结果。第二阶段新增的气泡、头像框和 HUD 绘制像素由并行的外观回放验证。

原始 JFR、游戏循环 CSV、动作分段、截图和运行配置在本工作树 `build/phase2-perf` 的 `phase2perf-pair-*` 子目录。单轮的 `launcher.log`、`run.json`、`frames.jfr`、`frames.csv` 和 `switch-summary.json` 可复核动作和统计。同进程补测在 `phase2perf-selector-serial`，另含 `selector-summary.json`。驱动、汇总脚本和六轮原始证据归档在 `build/phase2-perf/phase2-perf-evidence.zip`。
