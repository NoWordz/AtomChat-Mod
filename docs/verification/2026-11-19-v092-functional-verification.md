# AtomChat 0.9.2 功能验收

2026-11-19，Windows、隔离 Fabric 1.21.1 单机、AtomLib 0.6.0、RTX 5060 Laptop GPU。游戏内功能和帧时间所用的 Fabric 包 SHA-256 前缀为 `5db602ea70a4`。游戏内通过实际点击处理走面板入口，测试图片和聊天内容均为隔离实例的素材。

## 表情与反应

- 实际点击打开表情面板，核对编辑器和反应共用的 182 项顺序。点击新增 🙃 可插入编辑器。公屏消息支持实际右键选择同一表情，服务器确认后客户端显示反应。
- 发现并修复 Fabric 接收反应 ID 的次序问题。服务器先送出 ID 和对应指纹，旧接收器已处于客户端线程，却再次将处理排队。日志显示公屏消息先绑定到空 ID，随后完全相同的指纹才进收件队列。现在直接处理原接收回调中的 ID，保留来源连接检查。旧 JAR 诊断见 `feature_reaction_trace/launcher.log`，新 JAR 的实际反应快照见 `feature_smoke_final/feature-launcher.log`。
- 游戏内验证 Emoji 和贴纸可滚动、颜文字页签可切换、读取 42 张本地测试图和集成服务器下发的一张贴纸。另用同档截图核对网格。0.9.1 展开样本中的三行贴纸起始位置比展开后低 4、5、7 像素，候选已显示行的差值为 0–1 像素。原图分别位于 `feature_baseline/` 和 `feature_smoke_b/`。现有用例覆盖上传入口的本地添加、扫描及格子行为。本轮没有操作原生文件选择器。

## 表情面板性能

42 张测试贴纸时，诊断记录显示每次主线程贴纸扫描耗时 79–91 ms。普通 Emoji 页已省掉扫描。贴纸页仍刷新本地和服务器的文件，检查一次目录链和每个文件类型，并在提交结果前复核目录链和文件夹身份。首次读取预览时重新验证路径并用 `NOFOLLOW_LINKS` 打开文件。Windows junction 用例模拟目录被换成链接再恢复，确认先拒绝读入，目录恢复后可重新显示。

在同一存档和窗口设置下，用 0.9.1 安装包副本和 0.9.2 实测包各跑 6 圈，第一圈记为冷路径，后 5 圈记录点击首帧中位数。计时轮次没有截图。

| 操作 | 0.9.1 热首帧中位数 | 0.9.2 热首帧中位数 | 0.9.2 最慢热首帧 |
| --- | ---: | ---: | ---: |
| 打开 Emoji | 91.34 ms | 4.51 ms | 5.88 ms |
| 切到贴纸页 | 92.67 ms | 12.66 ms | 14.33 ms |
| 从贴纸页关闭后再开 | 91.94 ms | 12.80 ms | 13.72 ms |

实测包的冷开 Emoji 首帧为 117.68 ms，冷切贴纸首帧为 25.45 ms。测试里的首次滚动也有长帧。热滚动首帧中位数约 4.1–4.4 ms。诊断扫描记录为 `feature_scan_trace/launcher.log`，游戏整帧数据见 `feature_perf_before/`、`feature_perf_verified/` 及 `feature/emoji-performance.json`。

## 卡片与壁纸

- 在运行中的世界、Cobalt 和自定义条纹壁纸上核对卡片磨砂。自定义壁纸样本关闭面板背景模糊、卡片底色设为 0%，卡片模糊分别设为 0% 和 300%。相同区域的头栏条纹亮度对比度由 87.82 降至 19.42，卡片间隙和非卡片内容区分别保持 85.36 和 87.70。圆角、移动遮罩及主帧缓冲 alpha 另有原生像素回归。
- Cobalt 经正常生成和应用入口切换成功，退出并重启同一个隔离实例后恢复。原有 7 张壁纸此前已完成生成和视觉对照。

## 新年烟花

- 在本地集成服务器发送简体中文和英文，分别在面板打开和关闭时真实播放。繁体中文通过测试私聊行进入正常收件存储，面板关闭时播放。该用例覆盖私聊触发及 HUD 绘制，使用本地构造的私聊来件。
- 实验性内容关闭后不播放。固定时钟用例覆盖结束和冷却，消息入口用例覆盖引用、链接、历史和身份未知等过滤。拆除的旧实验特效及文案由当前资源和对应回归核对。
