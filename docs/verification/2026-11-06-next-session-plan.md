## 3. 测量协议（先修尺子，否则后面全是噪声）

### 3.1 已证伪的旧协议

「顺序走 A→B→C→D 各 20 秒一次」有两个致命问题：

- **整场有 0.4ms 级漂移**（同档极差 B 0.436 / D 0.406），而我们要测的效应只有 0.1–0.3ms。
- **C 档被 400 帧锁压平**（极差 0.018），对漂移**完全失明**，不能当基准。

### 3.2 新协议（强制）

1. **交替而非顺序**：`A B A B A B`（或 `A D A D`），每档 **10–12 秒**，**4–6 个来回**。
2. **只用相邻配对求差**：第 i 个 A 与第 i 个 B 相减，取中位；**禁止把不同时刻的窗口合并求中位**。
3. **给 C 档解盲**：临时把 400 帧锁放到 600（或改用天然低于 400 的场景/更高分辨率窗口），让 C 重新具备漂移可见性。**测完必须改回 400。**
4. 记录每个配对的时间戳，报告里给出「配对散点」而非单一均值。
5. 一次只变一个因素；不同因素不得相加。

### 3.3 仪表本身要先标定（新实验 E0）

**目的**：确认 0.1–0.3ms 的差异不是我们自己的诊断代码造成的。

- 加一个 `measureOnly` 开关：`Truth3Probe` 的帧探针**照常输出**，但 `FrameProfile` / `FrameSegments` / `PrepassProbe` 全部关闭（复用现有 `enabled` 门控）。
- 对比：`debug=on 全仪表` vs `measureOnly`（仅帧探针）。
- 判据：若差 >0.05ms，则**此前所有绝对值都要减掉这个偏移**，并在总纲里标注。
- 参考：`FrameProfile.enabled` 已由 `debug` 驱动（`FrameProfile.java:59,103,154`），`FrameSegments.start` 在 `current()==0` 时返回 0（`FrameSegments.java:36`），所以关闭路径天然近零成本。

## 4. 三个对照实验（主线）

### E1 —— 外部尺子：AC 的 UI 是不是异常贵

**问题**：用户质疑「如果 CPU 是瓶颈，为什么别的 mod 的 UI 不掉帧」。我们从未在同机同场景用同一把尺子量过。

**做法**（都在 `1.21.1-CCB`，同一场景站位、同一视角、同一分辨率）：

| 组 | 状态 | 说明 |
| --- | --- | --- |
| G0 | 无任何屏幕 | 纯世界渲染基线（= 现有 C 档的近亲，但完全无 Screen） |
| G1 | 原版 `ChatScreen`（按 T 打开） | 原版也画一列文字，是最接近的官方对照 |
| G2 | 原版物品栏 `InventoryScreen` | 另一个原版 UI 参照点 |
| G3 | AC 面板 · 完整 | 现有 A 档 |
| G4 | AC 面板 · 内容清空（新增 E2 的 mode） | 见 E2 |

- 尺子：`frame_probe`（屏幕 render 入口相邻 `nanoTime`），**必须与 G0 同源**——因此需要一个**不依赖 AC Screen 存在**的采样点（见 §6 实现要点）。
- 判据：若 `G3 − G0` 与 `G1 − G0` 同量级（±0.1ms），则 **AC 不异常**，400 目标属于「这台机器上任何 UI 都要付的代价」，该收手或改目标；若 `G3` 显著更贵（≥2×），AC 有硬伤，继续挖。

**这一步是整个计划的分水岭**：它决定后面是「优化」还是「重新定目标」。

### E2 —— 剂量响应：成本是固定的还是随内容长的

**问题**：0.27ms 花在「固定开销」还是「逐图元」。

**做法**：新增一个**仅 debug 可用**的剂量档（可与现有 A/B/C/D 并列，也可做配置项，避免再加热键）：

| 子档 | 画什么 |
| --- | --- |
| P0 | 面板底板 + 圆角 + 背景模糊，**无点阵、无文字、无列表** |
| P1 | P0 + 静态点阵/边缘（`DOTS`） |
| P2 | P1 + 文字（`DRAW` 的文本部分） |
| P3 | 全量（= 现有 A） |

- 判据：若 P0 已经吃掉大部分 `A − G0`，则**成本是固定的**（桥 / 全表面合成 / 同步）→ 静态层缓存与减 pass 都打不中，应查桥与合成；若成本随 P0→P3 近似线性增长，则**是逐图元**→ 静态层缓存 + 脏区直接有效。
- 该实验**只做诊断**，不改产品默认，不改视觉。

### E3 —— 回归审计：0.3.2 的那 0.2ms 丢在哪

**背景**：0.3.2 热态聊天 380–390 FPS；现在 D 档 361。模糊线已被 D 排除（`D − B = 0.009ms`，即使把 30Hz 调成 0.3.2 的 2Hz 最多也只再赚 0.009ms），所以 **0.13–0.19ms 的差额另有来源**。用户担心「更好的写法被替换」。

**基准已钉死（见 `2026-11-06-baseline-0.3.2-identity.md`）**：

- 0.3.2 包内 `atomchat-build.properties` 写 `git_commit=3f324e3` + **`git_dirty=true`**，但字节码指纹（`SkiaGraphics.class` 含 `ColorType`、不含 `SurfaceColorFormat`）证明**实际已包含 `34299d29` 的 Skija 0.143.18 迁移**。
- ⇒ **源码基准 = `34299d29`（2026-10-21 12:53，`mod_version=0.3.2`）**；类清单 265=265 无增删；`34299d29..a1dff96b` 之间除 `a1dff96b` 外无其它渲染提交。
- 用法：`git worktree add D:/AtomChat-032 34299d29`（独立工作树，**不动当前脏工作区**）。构建跑不通就只交静态结论。
- 已知不确定性：`git_dirty` 的确切内容无法还原，实测对照只能代表「34299d29 版本」，0.02ms 级差异需考虑此不确定度。

**两步走，先静态后实测**：

1. **静态对照（先做，零风险）**：以钉死的 0.3.2 等价基准（见上）为对照，逐项比较 0.3.2 与当前 `PanelBlurRenderer` / `SkiaGraphics` / `SkiaFontRenderer` / `DotTexture` / 桥（`SkijaRenderBridge`）的调用链，列出「新版多做了什么 / 少做了什么」，标出**任何新版更贵的写法**（多一次全表面清屏、多一次上传、多一次状态往返、多一层中间纹理）。
   - 现成素材：`build/astra-performance-20261105/old-*.javap.txt`、0.3.2 源码标签、0.3.2 的 render profile 日志。
2. **实测（可选，视静态结论）**：在**独立克隆**（**禁止在脏仓 checkout/bisect**）里给 0.3.2 打上同一个 `frame_probe`，构建一版候选包，与当前版本做同协议对比。若构建链走不通就如实停手，只交静态结论。

**判据**：能指名道姓说出「哪一处写法变了、贵了多少」，否则不得据此改代码。

## 6. 实现要点（给执行者，避免踩老坑）

1. **屏幕无关的帧采样点**：现有 `frame_probe` 挂在 `AtomChatScreen.render`，E1 的 G0/G1/G2 都没有 AC Screen。两种做法择一：
   - 挂在 `Minecraft#runTick` 尾部或 `GameRenderer#render` 的固定点（不受当前屏幕影响）；
   - 挂一个 `ClientTickEvents.END_CLIENT_TICK` + `WorldRenderEvents.LAST` 的组合，取相邻 `nanoTime`。
   - 要求：**同一采样点覆盖所有对照组**，A/B/C/D 语义不变，切档仍重置窗口。
2. **别再加新热键**：档位已用 F6（295）/ 备 Ctrl+Shift+F6。新实验优先走**配置字段**（`diagnosticRenderMode` 已有先例），避免键位冲突。
3. **三端同步**：任何改到 `AtomChatScreen` / `PanelBlurRenderer` 的改动，Forge / Fabric / NeoForge 三份都要；`layers/mapping/official/` 与 `platforms/1.21.1-fabric/` 是孪生。
4. **`PanelShellWiringSourceTest` 的 one-transform 契约**：`PanelOpenMotion.PanelRect capture = PanelOpenMotion.blurCapture(` 在每个 `AtomChatScreen` 里**只能出现 1 次**。加剂量档时**不要复制整块 preUi**（上一轮就是这么把三端构建弄红的）。
5. **构建**：三端隔离快照（`build/mode-d-20261106/prepare_snapshot.py` 可直接改路径复用），`--offline --no-daemon`；NeoForge 需预置 `minecraft_assets.properties`（SHA `015d0bc7…`）；工作区 `versions/atomlib.json` **一字不动**。
6. **想验证离屏像素一致性**：复用 `build/mode-d-20261106/ModeDCadenceProbe.java` 的写法（真实 shader + readback + 变异红灯）。
7. **实例**：Fabric `1.21.1-CCB`（debug=true，档位 `"A"`）；Forge `1.20.1-main` 的 AC 已被手动停用（`.disabled`），**不要动**；NeoForge `Mechanomania-航空学`。部署前必须确认游戏进程 0，备份 + 哈希回读。
