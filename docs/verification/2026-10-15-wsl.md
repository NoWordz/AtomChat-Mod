## 字体：环境缺少泰文字形

- 实例 JAR：`/home/niuqu/.local/share/PrismLauncher/instances/1.21.1/minecraft/mods/atomchat-Fabric-1.21.1-linux-x64-0.3.0-Preview.jar`；启动摘要 SHA-256 前缀 `b0620c78cafd`。
- `fc-list :charset=0e05`、`fc-list :charset=0e51` 和 `fc-list :lang=th` 初始无输出。Noto CJK 与 Color Emoji 已安装，不能提供所缺泰文字形。
- 执行 `sudo -n apt-get install -y --no-install-recommends fonts-tlwg-garuda-ttf`，退出码 0，安装版本 `1:0.7.3-1`，新增磁盘约 359 KB；安装触发字体缓存更新。
- 用上述 JAR 的真实 `SkiaFontRenderer.fontFor` / `drawRuns`、bundled.otf 及内嵌 Skija Linux native，扫描并绘制源码全部 29 条内置颜文字。
- 对照 Fontconfig 配置只列安装前的 DejaVu / Ubuntu / Noto 字体目录，排除 Garuda：`uniqueMissing=2`，U+0E05 / U+0E51；PNG 复现首屏相同四框，Java 按探针约定退出码 2。
- 正常系统配置：U+0E05 → Garuda glyph 214，U+0E51 → Garuda glyph 286；`items=29 uniqueMissing=0`，Java 退出码 0。已亲眼核对两张 PNG。
- 实际入口 `python3 /mnt/d/AtomChat-Main/.work/2026-10-15-linux-font/font_probe.py`；对照附 `FONTCONFIG_FILE=.../fonts-before.conf` 和 `baseline` 参数。脚本和离屏图保存在 `.work/2026-10-15-linux-font/`；用户原截图另存上方耐久路径。

离屏证据覆盖这台 WSL 当前 JAR 的字体回退和绘制；随后用户已确认游戏内颜文字问题解决。不能据此保证任意 Linux 字体配置都不缺字。

## 性能：软件渲染与无效实例环境变量

- 原游戏日志 22:51:38：`OpenGL Renderer: llvmpipe (LLVM 20.1.2, 256 bits)`。渲染器初始化早于 AtomChat 面板打开（22:52:12）。
- 独立 16×16 EGL 探针默认同样 llvmpipe；加 `GALLIUM_DRIVER=d3d12` 改用 Intel UHD；再加 `MESA_D3D12_DEFAULT_ADAPTER_NAME=NVIDIA` 改用 RTX 5060 / OpenGL 4.6，三次探针退出码均 0。探针有 DRI3 警告，但最终上下文成功。
- Prism 11.1.1 实例配置原为 `Env={GALLIUM_DRIVER:d3d12, MESA_D3D12_DEFAULT_ADAPTER_NAME:NVIDIA}`，不是有效 JSON；官方 `createEnvironment` 经 `Json::toMap` 读取 Env。ConfigVersion 1.3 使用 Qt INI。
- 确认没有 java 游戏进程后，关闭闲置 Prism，按字节备份实例配置，仅将 Env 改成 Qt INI 内合法 JSON 字符串。备份 `.work/2026-10-15-linux-font/instance.cfg.before`；修改前/后 SHA-256 为 `c16e286dc6e4504dd0135899790810023a4ab830a3d1673713c480a290149477` / `06122527261503f7e2b78c3cce21771eb0b42cb437954a6722edbed24b4e3356`。未改系统全局环境。
