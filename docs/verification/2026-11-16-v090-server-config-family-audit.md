## 证据与范围

- 用户实机截图：[托管页](../evidence/2026-11-16-v090-server-config-review/user-server-hosting.png)。可见：只有标题的独立卡片、大块灰色输入面、没有设置页的图标分组栏和卡片说明、保存按钮靠近面板下缘。hover、动效及其他分类的交互问题来自用户反馈，不能从这一张静态图单独证明。
- 直接族群调用盘点：[清单](../evidence/2026-11-16-v090-server-config-review/family-source-inventory.json)。扫描 shared、official mapping、三个 platform 的 main Java，命中 44 个文件。这是调用关系盘点，不是 44 项缺陷，也不是全应用实机视觉验收。
- 参考实现包括 SettingsHomePage、SettingsSectionPage、ConversationListPage、ProfilePage、BottomTabBar、UiLayout、SettingsGroupIcons、SettingsGroupGlyphs、ConfirmationSurface、QuickPhrasePanel / QuickPhraseWiring，以及现有 AtomLib UiCards / UiTokens。
- 配置页为 shared 实现；设置详情有 official / Fabric 映射孪生，Screen、配置网络和个人资料服务端仍有三个平台接线。后续不能只修 Fabric。
- 本轮没有重跑构建或测试。部署前的构建与行为测试结果仍见[实现记录](2026-11-16-v090-implementation.md)，不能据此声称本次新增设计已经实现或通过。

## 审计发现

| 项目 | 当前事实与影响 | 修正方向 |
|---|---|---|
| 卡片交互 | ServerConfigPage.render 给 UiCards 的 hoverWeight 直接传 0 / 1；页面没有设置页的 rowHover 渐变、PressScale 行反馈或 UiStagger 内容入场。复用了表面，没有复用完整交互。 | 接回设置卡片现有 hover、press、入场与全局动画开关；动画后的绘制和命中保持一致。 |
| 开关交互 | setInteraction 使用整张卡片作为开关 hover，pressed 固定 false；点击只有 toggle pulse。与设置页按实际开关区域驱动的反馈不同。 | 对齐设置页卡片与开关的分工，保留既有点击范围约定。 |
| 分组副标题栏与图标 | 页面 Row 只有 id / key / toggle，未定义 LABEL 分组，也没有调用 SettingsGroupIcons。缺少现成的图标、点阵、分隔线及折叠层级。 | 复用设置页分组栏完整样式；SVG 从既有图标按语义选取，缺失才补画。 |
| 卡片副标题 | 当前只绘制标题。范围、单位、留空规则全部挤在标题里，没有字段描述。已有 section / hint 翻译并不代表已画出来。 | 为每个字段提供标题、用途说明、单位及约束，说明参与高度计算和窄布局换行。 |
| 输入框材料 | SettingsFieldPaint.surface 沿用旧数值编辑器的 trackRest 灰底和 rim。设置页的历史保留天数也调用它，因此不能只改新页面。 | 统一设置页与服务端表单输入：轻底细边、主题自适应、柔和 hover、强调色焦点、字段旁错误提示。数值紧凑靠右；长文本使用全宽编辑区。 |
| 编辑行为 | 点击字段始终把光标放到末尾；没有按文字位置定位、拖选、上下行移动和撤销；按 UTF-16 单元移动/删除可能拆开补充字符。多行框随常用语行数增高，不能替代列表管理。 | 使用明确的表单编辑模型和共享编辑能力；覆盖光标、选区、剪贴板、Unicode、键盘导航及实际中文输入。 |
| 固定保存布局 | ServerConfigLayout 以 DETAIL 的 list.bottom 为按钮底边；该位置采用 LIST_PAD_X，并未采用导航底栏的 PANEL_BOTTOM_PAD 及内部留白。 | 外边距和按钮内缩以导航底栏为参照；固定操作区有独立布局，绘制、命中、滚动裁剪共用几何。 |
| 常用语流程 | 当前把整个 List<String> join 成一个多行字符串；缺少逐条新增、编辑、删除、排序和限额反馈。 | 改为资源包内的常用语列表和单条编辑页。 |
| 资源包信息结构 | ServerPack 同时包含 files、phrases、serverName、icon。将常用语列成同级顶层 tab，拆散了同一份下发内容。 | 顶部改为托管 / 资源包 / 消息模板。资源包内组织基础信息、表情包、常用语和同步状态。 |
| 表情包管理能力 | ConfigPayloads.PackStatus 只有数量、体积和 hash；Refresh 仅重新扫描服务器目录。没有管理文件清单、缩略图、导入和删除的界面接口。 | 增加服务端表情包清单、面板内预览/导入/删除，并纳入同一份保存事务。服务器资源目录是 CacheDirs.serverEmotesDir()，不能借用玩家个人表情目录。 |
| 消息模板缺项 | ServerConfigValues 没有模板字段；没有服务端模板保存、下发、编辑和预览。ChatTemplates 只是客户端配置文件中的两组模板，仍有 knownNames 等限制。 | 增加明确的服务端模板模型、验证、保存和下发，以及列表 / 单条编辑 / 样例预览。不能只给旧字符串列表加界面就宣称模板识别能力完成。 |
| 配置覆盖不完整 | maxProfileTotalMb 在 AtomChatServerConfig 和三端 ProfileCompanionServer 中实际使用，但未进入 ServerConfigValues / GUI。它与旧头像库是不同的存储。 | 托管页补上个人资料图片库容量，并明确与媒体库、旧头像库的区别。 |
| 服务端与客户端限额不一致 | ServerConfigValues.MAX_PACK_MB_LIMIT 为 64；PackSyncClient.MAX_BYTES 为 16 MiB，onManifest 会拒绝超限资源包。服务端可保存客户端无法接收的值。 | 统一有效协议限额、服务端校验和界面提示；旧客户端兼容也要按其真实能力处理，不能只扩大界面数字。MiB / KiB 标签与字节换算保持一致。 |
| 草稿状态与反馈 | 保存按钮没有依据 dirty / 有效性禁用；成功反馈不随随后编辑清除，错误主要是整页文案。 | 区分未修改、未保存、字段错误、提交中、保存成功、部分客户端同步失败；修改后不继续显示此前“已保存”。错误可定位字段。 |
| 保存与下发生效 | onSave 持久化配置并 invalidate pack；当前主要由客户端进服请求内容，没有对应的管理员保存后在线刷新流程。重扫当前还会 invalidate 现有包，不能当作无副作用的草稿操作。 | 保存后更新允许接收的在线客户端；扫描、导入、删除和草稿预览不能提前发布未保存内容。配置保存成功与客户端同步成功分开反馈。 |
| 验证覆盖缺口 | ServerConfigPageTest 显式关闭 animationEnabled，渲染时鼠标位于 -1 / -1，主要验证截图可生成、固定保存几何与保存/返回逻辑。 | 补充与现有组件同状态的对照，覆盖 hover 中间帧、按下/释放、入场、动画关闭、焦点、字段错误与窄布局；保留实机 IME / 全页操作验收边界。 |

水波反馈不因页面源码没有直接出现 ripple 就判定缺失：UiCards 及按钮会登记区域，Screen 负责 ClickRipples。后续应核对完整接线和实测，不新增另一套水波系统。

## 已确认的第二轮决策

1. 顶部内容采用托管、资源包、消息模板。常用语和表情包属于资源包；不为凑分类新增无实际能力的配置。
2. 模板采用列表进入单条编辑。条目有名称、公共/私聊类型、可插入占位符的格式、样例输入、实时字段提取结果和歧义提示。公共、收私聊、发私聊的具体字段契约在实现前写清。
3. 表情包管理支持面板内预览、本机导入和删除，复用现有表情包族群。
4. 常用语支持逐条新增、编辑、删除、上下排序；从列表进入单条编辑页。
5. 设置页与服务端配置页的表单输入改为轻底细边，数值紧凑靠右、单位在旁，名称/常用语/模板等长文本使用全宽编辑区。
6. 所有配置、常用语、模板及表情包增删，统一保存后生效。导入阶段可暂存，但未保存的文件不能进入对外下发包；放弃草稿撤销暂存操作。
7. 保存后同步已允许接收相应内容的在线客户端；不打断聊天。同步失败保留上一份可用内容，提供可重试状态。
8. 单条编辑页返回/Esc 保留到总草稿；无效编辑不丢失，标出错误并阻止最终保存。离开整个服务端配置页才询问是否放弃。“完成”用于结束当前编辑并返回，不是第二套对外提交。
9. **本次只做服务端下发模板，不增加客户端本地模板编辑器。** 没有 AtomChat 服务端模组的服务器，客户端仍手改原有配置文件。

继续有效的原决定：命令是服务端配置唯一入口；不加设置首页卡片和根 tab；返回原聊天；保存成功留当前分类，以权威回执更新基准；权限检查、错误保留草稿、现有主题与 SVG 复用均保留。

## 模板能力边界

- 这是辅助客户端解释现有聊天插件格式，不是修改 TrChat 等插件的服务器聊天输出。
- 服务端配置页依赖现有 AtomChat 服务端模组；本次不新增延期的 Paper/Youer 配套插件。
- 匹配正文和名字不等于得到真实 UUID / 皮肤。预览需要区分字段提取与身份依据，不能拿显示名补出错误身份，也不能把原生明确身份覆盖掉。
- 模板规则需要按服隔离，与已确认结构、身份冲突处理及原文富文本保留衔接。未知字段、缺字段、多重匹配及私聊方向冲突需要明确结果。
- 人工配置并下发的模板仍属于模板补救，不混入纯客户端自动识别 90% 的成绩。首次陌生离线跨服缺身份/皮肤资料的缺口仍在。

## 修订实施顺序与验证

1. 先完成族群与表单输入的共用部分：设置页和配置页共同消费同一份字段表面、交互与错误状态；复用分组栏、卡片动效和底栏几何。避免复制另一个 SettingsSectionPage，也不能让服务端草稿写进 AtomChatConfig。
2. 建立总草稿和嵌套编辑页，接入常用语列表、个人资料库容量、资源包清单/预览/导入/删除；使配置与资源文件在保存确认之前均不对外生效。
3. 实现服务端模板契约、样例验证、持久化和下发，以及保存后的在线更新。明确客户端能力差异、旧内容保留与失败重试，继续复用已有按服隔离和身份判断。
4. 按最终行为集中独审一次；先跑有意义的行为和原生渲染用例，再完成三端构建与当前 JAR 校验。已有有效检查可复用，不放宽视觉阈值或批量接受孪生台账。
5. 用同屏参照检查设置页与配置页的静止、hover、按下、焦点、错误和禁用状态；中英文、深浅主题、窄面板和已有动画设置均覆盖。离屏图不替代真实游戏中的 IME、滚动、返回和保存体验。

当前三个实例仍是 19:57 部署的旧候选。本报告及 grill 决策尚未落到运行包，不能把本轮审计写成修复完成。


## 草图阶段主代理审查

首轮草图已生成，见 `docs/evidence/2026-11-16-v090-server-config-review/sketch/`。这是主代理要求先看图的阶段性停点，不是完整实施交付。主代理查看了五张单页/总览、真实设置页参照及生成源，并核对实际常用语和资源配置代码。

发现以下修订项，已退回同一个 Franklin 子代理处理，未另派代理：

1. 常用语编辑文案“点击后发送”与实际填入 composer 的行为不符，需改为填入聊天输入栏。
2. packName 实际是服务器显示名覆盖项，留空回退 MOTD；草图“资源包名称”会误导其用途。
3. 缺消息模板列表入口与管理状态；单条编辑页缺已约定的完成/回列表动作，应明确它不提交服务器，真正保存仍统一提交总草稿。
4. 分类 chip 的高度、字号和圆角使用了近似常量，与实际设置页 token/布局公式不一致，需取真实公式。
5. 当前只体现深色宽布局及成功例，需要补字段状态与无匹配/歧义示意。动态反馈、窄布局、浅色和真实IME仍不能据此宣称验收通过。

确认可保留：图标分组、点阵/分隔线、组卡内部行分隔、紧凑数值/单位、服务端资源归属、总草稿提示及保存条内外留白。合并组卡确有真实设置页先例，不应误判成自造布局。

本次主代理审查没有跑业务测试，生产Java与已部署包尚未因草图改变。修订草图返回后再核对受影响项；未将本次结果记为完整实现通过。
