# 字体、背景与性能：采样状态

本次禁止代理启动游戏。背景着色器离屏样本与字体测试不等于游戏内验收；没有纯净实机场景，因此尚未确认性能根因或帧率提升。

现有量具：`FrameProfile` 和 `FrameSegments` 需启用 AtomChat 的 `debug`，每 600 个面板帧报告最近窗口；`DRAW` 只覆盖绘制回调，不包括桥接准备、flush/submit、状态恢复或 GPU 完成。各段存在嵌套，不能相加；不同滚动窗口的分位数不能相减。`com.atomchat.UiFrame` JFR 事件记录页面、面板耗时、相邻帧间隔和面板帧号。`com.atomchat.PanelSegments` 记录同一面板帧号、页面、桥接前段、绘制回调及桥接后段；通过非零帧号配对，某一事件缺失时不得靠相邻顺序补配；`com.atomchat.Navigation` 记录动作、页面及当前帧号（帧外动作的编号为 0，需按 JFR 时间戳对齐）。帧号并非游戏整帧编号。

锁定 AtomLib 桥接没有公开内部计时回调，桥接前段包含状态捕获和上下文准备，后段包含 flush/submit 和状态恢复，不能再将它们拆成分别测得的值。构造、配置读取、首帧及游戏内非阻塞 GPU 计时尚未接入，因此当前构件不是完整性能诊断包。离屏探针仅证实本机支持 ARB_timer_query，第一次查询未就绪、下一帧可用；不代表游戏运行时可用或其结果。请勿把现有日志作为因果结论。

后续由用户自行启动并采样：从启动起关闭光影，固定游戏版本、加载器、整合包、Java、GPU/驱动、分辨率、相机、壁纸、GUI 尺寸、垂直同步及帧率上限；记录 AtomChat 与 AtomLib 两个实际 JAR 的 SHA-256。分开记录关闭面板、稳定聊天、各目标页面、重复打开、固定路径切页；每段标注开始结束时间和操作，并保存日志、JFR、外部逐帧时间与亮暗背景截图。涉及个人聊天内容、服务器地址和路径时由用户检查后再分享。

点阵或其他热点需要在同一场景交替 A/B，保留画面对照并报告整帧 p50/p95/p99、同帧各段、GPU 查询可用性与延迟；不能将历史混合窗口中位数当作主瓶颈。既有基础采样步骤见 `2026-11-04-render-performance-final.md` 的 Manual in-game sampling，但其中旧构件哈希不适用于本次改动。
