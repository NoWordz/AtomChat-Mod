# AtomChat 0.9.8 实施计划

**目标**　让附属 Mod 能通过 Java API 调整 AtomChat 的组件和页面，同时完成特殊卡片、公屏头像、兼容调查、缓存审计和渲染优化。

**基线**　AtomChat 0.9.7 主线提交 `2b4d3249`，AtomLib 0.7.1。支持 Fabric 1.21.1、NeoForge 1.21.1、Forge 1.20.1。保持 Skija GPU 离屏路径，沿用现有共享源码、Official/Yarn 映射和 [UI 回归约定](../../UI_CONTRACT.md)。

**分工**　主代理负责 API、JEI 示例、Mod 兼容调查和集成。子代理一负责特殊卡片、HUD、TPA 和公屏头像。子代理二负责缓存审计、性能基线、优化与「平衡」降采样。三路以同一主线提交开独立工作树。

## 共同约定

- 用户确认开发者是扩展对象。入口为公开预览 Java API，三个加载器共用公开契约。新接口后续如需调整，附迁移说明。现有 0.9.7 卡片接口与混装回退继续兼容。
- 内置界面与附属 Mod 使用同一套注册和布局逻辑。编辑器、焦点、输入法、发送、导航栈和资源生命周期由宿主管理。保留开箱默认布局、画质及交互。
- 阴影、模糊和缓存相关实验使用隔离实例和实测对照。真实游戏性能与离屏测量分别记证据。测试用实例、工作树、源文件所有权与验证记录在各路交接时列明。
- `ChatHudRenderer` 的卡片布局和绘制由子代理一修改。子代理二先在诊断和渲染基础层推进，在交接中说明涉及 HUD 的改动与复测需求。两路在 `AtomChatScreen` 需要接线时分别限于服务端图片入口和界面扩展入口，按方法交接。
- 三路完成后集成并集中交叉审查。按任务实际需要补行为测试和原生像素对照。发布及推送另行授权。

## 主代理　开发者扩展与生态调查

### 1. 从物品卡和 JEI 跑通第一个外部消费者

- [ ] 对照 `shared/src/main/java/com/atom/chat/api/card/CardRenderRegistry.java`、两个映射的 `BuiltInCardRenderer`、面板消息列表及对应的卡片命中执行路径。让本地 Java 附属 Mod 为物品卡添加客户端操作，仍走现有按下反馈和实际命中区域。客户端自定义回调与服务端卡片载荷的动作分开，收到卡片时不能解析出任意本地回调。
- [ ] 以带命名空间的稳定 ID 标识扩展。登记添加、移除、替换和排序规则，附属 Mod 可以明确指定目标。覆盖未装附属、同一目标多个扩展、重复 ID、被移除的排序锚点与未知 ID。内置项和扩展项产生同一份供绘制及命中消费的快照。
- [ ] 增加可独立构建的 JEI 示例附属 Mod。用实际物品卡的解析结果打开 JEI 「查配方」，回退界面要能回到 AtomChat。验证物品 NBT、JEI 运行时不可用、没有物品和未装附属的情况。JEI 依赖仅由示例声明。示例最终覆盖明确的三端支持版本。

### 2. 把扩展接入真实 UI

- [ ] 输入栏与工具菜单。接入 `shared/.../tools/ComposerTools.java`、`ToolLayout.java`、`ToolMenu.java`、`shared/.../ui/UiLayout.java` 以及两套 Screen 宿主。插槽、菜单项和发送按钮均可增删、重排和替换，第三方可以调用宿主发送能力。窄面板、多行、剪贴板、Tab 补全、IME 及空插槽走实际入口复测。
- [ ] 导航。接入 `shared/.../ui/BottomTabBar.java`、`nav/NavPage.java`、`nav/NavStackController.java` 以及两个映射的页面宿主。新增自定义页、导航页签和路由显示次序，保留返回、恢复、转场与旧页面标识。覆盖窄面板、多页签和恢复时扩展缺席。
- [ ] 设置。接入两个映射的 `SettingsHomePage.java`、`SettingsCatalog.java`、`SettingsSectionPage.java` 与共享设置模型。支持修改设置首页入口、详情页页签、折叠组与设置行。覆盖滚动、折叠、恢复当前页签、语言切换和附属配置的读写责任。
- [ ] 样式。以现有 UiTokens、主题及组件几何为入口，暴露可调整的间距、留白、尺寸、颜色、图标和样式。绘制和点击共用实际布局。给示例增加菜单、页签、设置项和样式扩展示范，以内置默认三端画面与旧设置回放核对回归。
- [ ] 写开发文档，说明生命周期、ID、顺序、替换、样式与真实示例构建方法。用外部示例验证三端依赖方式，随后记录可反哺 AtomLib 的实现及其生产消费者。

### 3. 查现役整合包与联动机会

- [ ] 核对 Fabric CCB、Forge 主实例和 NeoForge 航空学中活跃的 Mod。以原版聊天入口、聊天头像/动画、NCR、ModernUI、Chloride、输入法、光影、HUD 合成为优先，复用 0.9.7 已证实的行为。对有证据的冲突记录复现步骤、触发版本、优先级和影响。
- [ ] 调查地图、配方、语音与频道的可用接口。记录玩家能获得的功能、三端可用性、服务端要求、与现有协议和权限的关系。JEI 示例由任务 1 实现，其他候选的调查以证据和可行方案交付。

## 子代理一　特殊卡片与公屏头像

### 4. 特殊卡片、HUD 与 TPA

- [ ] 在 `shared/.../api/card` 定义统一的特殊卡片展示语义，沿用 `ShareCard` 的既有协议，涵盖坐标、物品、TPA、红包和其他注册卡片。面板、收消息、HUD 使用同一分类和状态。图片保持独立的消息类型。
- [ ] 让 `shared/.../render/ChatHudRenderer.java` 调用可测量、可绘制的紧凑样式。现有卡片默认缩小显示，第三方可选自定义紧凑样式或仅在面板显示，缺少紧凑实现时复用通用缩略卡。按屏幕物理像素绘制，沿用 HUD 消息生命周期、屏蔽、淡入淡出和消息数量规则。游戏 HUD 负责展示，动作由面板处理。
- [ ] 在 `UniversalCardMatcher.java` 及两套 `BuiltInCardAdapter.java`、`CardActionExecutor.java` 的现有入口扩展 TPA。优先保留消息自带的按钮与原命令，已测的纯文字格式通过明确规则接入，能确认请求但缺可靠动作时显示只读卡。测试 StellarRTP、EssentialsX、HuskHomes，关注两人同时发请求、乱序、拒绝、过期、断线切服、不同语言、普通聊天误匹配和旧客户端回退。分别报告服端协议和客户端显示证据。

### 5. 管理员编辑公屏头像

- [ ] 接入 `ServerConfigPage` 和两个映射的 `ImageCropper`。管理员从本地选图、预览裁切、确认保存或恢复地球图标，普通玩家读取已发布结果。跟随现有管理权限，服务端验证尺寸、格式和配额，保存与广播保持一致。
- [ ] 沿用 `ConfigAdminServer`、`PackSyncClient`、`ServerPackStore` 的管理与接收生命周期。验证先装旧客户端或旧服务端、接收开关即时切换、切服、重连、管理员换图、保存失败、上传非法内容和普通玩家无写权限。默认地球图标用作无图、拒收、同步失败的回退。
- [ ] 在两套 `ConversationListPage` 把公屏默认图标、图片裁切和背景接到全局圆角半径与连续曲率。对照圆角 0、默认和上限，包括非整数 GUI 缩放、透明图片、深浅主题。

## 子代理二　渲染基线、缓存审计与优化

### 6. 建立 0.9.7 基线并定位瓶颈

- [ ] 在隔离 CCB 复用现有 `FrameProfile`、JFR/GPU 计时、像素及回放设施。记录基准提交、使用的 JAR 与 AtomLib、模组/配置、GUI 缩放、渲染分辨率、画质、世界视角、预热和重复条件。
- [ ] 同场景获取关面板、静止聊天及设置、长列表滚动、切页、首次打开、HUD 等样本。保留 CPU 提交、GPU 耗时、分段帧时、分配量和长帧原始记录。控制变量分别量文本布局及字形、模糊、阴影、离屏绘制与合成。根据收益定位到冷启动、稳态或交互，检查背景随世界变动的成本。
- [ ] 分阶段沟通首轮数据和可验证瓶颈，优先处理有实测依据的热点。继续验证不同背景、文字量、静止和变化画面，明确每次计量的适用范围。

### 7. 查缓存并做带收益的优化

- [ ] 盘点语言/布局、字体/字形、GPU 图像/纹理、图片派生层、颜色与效果缓存的所有者、容量、缓存键、失效与关闭路径。具体追溯 Chloride 的快速中英切换，以及贴图被按旧尺寸或低采样缓存复用的风险。
- [ ] 对确认的缺陷先证明旧行为，复用以当前语言实例为准的失效思路。核对主题、GUI 缩放和物理像素相位、画质、资源重载、GPU context/窗口变更、世界切换、图片/动画更新与原生句柄释放。场景变化后颜色、清晰度、动画和语言均回到当下状态。
- [ ] 优先复用可测量的稳定成本，限制临时与原生内存预算。滚动、动画、世界背景和动态物品频繁变化时按实测选择重绘范围。对每个优化配同场景前后 CPU/GPU 与长帧数据，检查是否把费用挪到上传、重建或下一帧。

### 8. 验证三档画质，继续优化「平衡」

- [ ] 对照 `GraphicsQuality`、`KawaseBlur`、`CardBackdrop`、`SoftShadow`、`HudShadow` 与文字阴影的既有档位。按测量进一步降低平衡档的模糊分辨率、阴影纹理密度或有效采样成本。固定光影背景、圆角曲线和缩放，确认平衡档正常游玩观感基本一致，文字、图像和边缘保持清晰。
- [ ] 保存极致、平衡、性能三档配对原图和帧时。覆盖静止与滚动、三个缩放级别、亮暗主题。用 CCB 对应可复现案例复测首次打开和动态交互。分别报告细微视觉差异与可感知卡顿变化。
