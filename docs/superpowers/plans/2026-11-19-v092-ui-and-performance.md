# AtomChat 0.9.2 实施方案

**目标**　改善切页和表情面板的帧时间，修正卡片阴影和表情包入场，加入独立的卡片磨砂和全屏新年烟花，微调现有 7 张内置壁纸。

**基线**　以当前已核对的 `origin/main`（`97a108cc`，AtomChat 0.9.1、AtomLib 0.6.0）为对照。实施前核对主线最新提交与实际待测包的构建来源。保留现有两个工作区的未提交改动，从合适的干净检出实施。

**环境**　沿用 Skija 和现有 GPU 绘制路径。交付目标为 Forge 1.20.1、Fabric 1.21.1 和 NeoForge 1.21.1。可共享的行为放在 `shared`，需要映射的入口同步修改官方映射层和 Fabric 对应实现。

验收记录见[功能验收](../../verification/2026-11-19-v092-functional-verification.md)。切页按已确认的两档结果收口。

## 1. 切页与表情面板性能

- [x] 先用 0.9.1 在同一个实例、世界位置、窗口尺寸、画质、帧率上限和模组组合下采集「聊天 → 设置首页 → 外观设置 → 返回」。区分首次进入、热切页、动画结束后的稳态，记录游戏整帧时间 p50、p95、p99 和长帧。同步使用 `FrameProfile`、`FrameSegments` 和已有 JFR 标记对齐导航动作。优先复用 CCB 实例和既有采样工具，基线与候选交替测量，确认结果超过重复运行的波动。
- [x] 在 `PageTransitionComposite`、各端 `AtomChatScreen` 和两套 `SettingsSectionPage` 中量出页面布局、入场首帧、转场命令录制与回放、合成和桥接各自开销，再处理占比高的实际热点。保留现有动画曲线、头栏稳定性、快速打断时的连续性、命中几何和教程交互。用现有转场逐帧验证检查普通前进、返回和连续切换。
- [x] 在两套 `EmojiPanel` 测量打开、切换页签、滚动以及图片首次显示。优先让布局计算、绘制和命中共享同一网格范围，限制渲染工作为可见行及其动画所需内容，并按测量结果复用文字和图片资源。结合 `EmojiPanelPerformanceTest` 的隐藏窗口探针与实机帧时间验证。离屏耗时和游戏整帧耗时分别报告。
- [x] 以切页长帧和高分位帧时间改善为主要验收。检查稳态、关面板 HUD、首次打开和热切换，防止开销转移。已完成修复前后两档 Fabric 整帧对照，最终 0% 和 300% 首次外观首帧分别为 11.36 和 11.64 ms，过渡各剩一帧超过 16.67 ms，详见[帧时间记录](../../verification/2026-11-19-v092-navigation-frame-times.md)。

## 2. Emoji 排序与表情包入场

- [x] 用共享 `ReactionEmoji` 维护同一份有序列表和反应校验。保留旧条目，新增黄豆脸和少量有梗的 Emoji。现有 💀、🗿、🤡 与同类靠在一起，动物、手势、爱心、食物等各自相邻。两个入口都用连续滚动网格，靠顺序归类。沿用「Emoji／颜文字／表情包」页签。
- [x] 两套 `EmojiPanel` 都移除表情包图片按行延迟、上浮的入场，在弹层自身开合坐标内从首帧就使用最终网格位置。保留弹层开合、切页签动效和悬停反馈。覆盖已有图片、服务器表情包、滚动、上传入口及教程沙盒。
- [x] 验证两个入口的新增表情及顺序一致，在游戏实际字体下显示正常，能正确插入和发送反应。覆盖新旧表情混合使用和动画期间的点击命中。

## 3. 卡片阴影与背景模糊

- [x] 让顶栏、输入栏和底部导航的外阴影跟随当前卡片不透明度，涵盖底栏变形和转场中的绘制。核对 `ShellHeader`、`BottomChromeTransition`、`BottomTabBar` 及其它同材质入口。卡片不透明度为 0% 时阴影为 0。
- [x] 在两套 `SettingsCatalog` 的外观控件中加入「卡片背景模糊」，取值 0–300%，默认 0%，与全屏面板的「背景模糊」分别控制。范围涵盖所有卡片，包含顶栏、输入栏、底部导航和页面中的卡片。同步处理外观页重置及 `AppearancePresetStore` 读写，旧配置和旧预设缺少新字段时取 0%。
- [x] 使用游戏场景或当前壁纸（内置和自定义）作为背景源。在绘制 UI 内容前生成卡片共用的模糊背景，再按各卡片实际绘制位置和圆角裁切，跟随窗口尺寸、壁纸裁切、页面与底栏动画。文字、图标及经过半透明栏位的滚动内容保持清晰。默认 0% 跳过卡片模糊渲染，积极复用同一帧的背景和模糊结果，避免为单张卡片单独执行模糊。核对 `PanelBackground`、各端 `PanelBlurRenderer`、`ChromeMaterial` 与共享背景合成边界，保留主帧缓冲 alpha。
- [ ] 卡片底色为 0% 时仍可有磨砂，两个滑块都为 0% 时底色、阴影和磨砂全部消失。做原生像素对照，覆盖世界、内置壁纸、自定义壁纸、0% 和 300%、不同 GUI 缩放以及几何过渡。验证已有背景模糊开关不禁用卡片模糊，且 GPU 路径失败时卡片和文字仍能绘制。

## 4. 趣味特效与新年烟花

- [x] 在「趣味特效」保留一个清晰的标题或开关文案，移除旧的「新年快乐」特效，保留其它已有效果。移除「实验性内容」里现有冲击波、结冰、黑洞等旧特效及对应入口和过时说明。保留「实验性内容」开关，沿用默认关闭和已有保存值。
- [x] 在 `ChatEffectEvents` 的新消息入口及各端的游戏屏幕绘制路径接入烟花。公屏、私聊以及自己刚发出并入列的玩家消息都可触发，面板打开和关闭均可播放，遵循实验性内容与全局动画开关。只在新消息正文中识别「新年快乐」「新年快樂」「Happy New Year」，不受界面语言影响。复用现有命令、链接、引用和代码片段排除规则，历史和系统消息不触发。用统一的会话状态与冷却避免同一条消息、两个绘制入口或密集消息重复启动。
- [x] 视觉做几束清晰的大烟花，错峰升空、绽放和淡出，约 2–3 秒，重点在屏幕上半部，保持中央视野与聊天文字可读，默认静音。用有限粒子数量和单一绘制路径，效果结束或开关关闭后及时停止绘制。以固定时钟检查关键帧及触发边界，实机覆盖面板打开和关闭、收到私聊和自己发送。

## 5. 内置壁纸

- [x] 小幅优化原有 7 张壁纸的高光、阴影和色调，沿用原名称、ID、顺序、构图及立体质感。预设数量保持 7 张。
- [x] 沿用现有的预览、应用、重启恢复和窗口尺寸适配。已验证全部 7 张可以生成，并按 480 × 860 像素与 0.9.1 对照。Fabric 壁纸生命周期、选择器与语言专项已通过，实机画面留待整版验收。

## 交付检查

- [x] 优先完成性能基线和现有热路径修复，再接入新增渲染。新增设置、壁纸和烟花可以分别验证，最后测完整候选以反映同时开启时的开销。
- [x] 三端执行适用的 `test`、`build`、targets、JAR、bare 与原生像素回归。集中独立审查会话生命周期、原生资源释放、卡片背景渲染、跨端接线和旧配置兼容，修正后复跑相关检查。
- [x] 如实区分本轮实机、离屏与静态检查。记录基线和候选包、使用的实例、首次和热切页结果、错误与跳过项。版本号及中英发布说明与验收结果一致。
