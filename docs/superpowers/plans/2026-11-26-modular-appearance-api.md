# AtomChat 可替换外观 API 实施方案

本轮先修复 0.9.8 候选版的问题。这个方案定义下一阶段公开预览接口的交付内容。

## 已确认的行为

- 独立 Java 附属 Mod 可分别提供气泡、面板轮廓、头像框和动态壁纸。用一个真实附属同时装上四个部件验收。三端共用接口，Fabric、NeoForge 和 Forge 分别验证。
- 玩家在现有「外观和交互」设置逐项选择，能混用不同附属。开箱即用的内置外观是每项默认值。现有按钮、菜单、导航、设置和卡片接口继续可用。
- 面板轮廓同时决定外壳绘制、阴影、模糊蒙版、内容与壁纸裁剪，以及面板内外的命中。内部布局、键盘、聊天路由、输入框和发送行为由宿主处理。
- 面板与 HUD 共用气泡和头像框的选择。作者可以为 HUD 提供独立画法；缺少对应画法时 HUD 使用内置部件。
- 动态壁纸接收帧时间、绘制范围及资源生命周期，用程序动画示例验证。第一阶段提供宿主绘制调用，视频播放和 GPU 管线由各自现有机制处理。
- 新的自定义外观预设保存现有外观字段和四项部件选择，包含静态或动态壁纸。附属缺失时使用内置部件并保留已选的 ID，重装后恢复。预设文件仍放在 `atomchat/client/presets`，当前设置仍放在 `config/atomchat`。

## 代码接线和实施顺序

### 1. 逐项注册、选择与预设

- [x] 在 `shared/src/main/java/com/atom/chat/api/ui` 添加外观接口并复用现有注册 ID 约定。每项使用带命名空间的稳定标识、翻译键和不同类型的实现；各项独立解析选择。注册或读取触发版本变化，绘制时复用已解析结果。
- [x] 从 `SettingsSectionPage` 的现有预设与外观入口挂接选项，Fabric 及 Official 映射同步。由 `AtomChatConfig` 持久化选择。玩家装两个附属时可各取其一，重开游戏后仍选中对应部件。
- [x] 扩展 `AppearancePresetStore` 的读取、写入、应用与回滚。动态壁纸记附属 ID；静态壁纸在预设目录内保存校验后的独立副本；显式无壁纸也是一种选择。旧预设缺少新字段时保留玩家当前对应选择。应用失败时还原原来的配置和壁纸。预设比较使用实际保存的外观字段与壁纸身份。
- [x] 用隔离目录测试老预设兼容、新预设恢复面板及卡片模糊和透明度、静态图片原件移动、动态附属卸载重装、配置写入失败，以及重开游戏后只有一个主题项显示选中。

2026-11-27，`a8b2ec4c` 通过三端全量测试和各 196 个既有原生场景，并部署到三个测试实例。隔离 Fabric 客户端实测两个独立附属的混搭、预设应用、卸载重装和壁纸切换时重开面板。四类部件的实际绘制接线见后续分节。

### 2. 气泡与头像框

- [ ] 以 `ChatBubble`、`MessageListView` 和 `ChatHudRenderer` 为入口。宿主提供消息气泡的现有内容边界、分组位置、自发标记和主题颜色，读取同一轮廓来画底色、裁剪媒体和定位需要沿轮廓的交互效果。内容测量由现有布局负责。
- [ ] 将面板和 HUD 的头像框挂接到 `MessagePaint`、`AvatarRing` 和相关绘制入口，包括使用自定义图或默认地球的公屏头像。头像图片解析与权限沿用原路径，框可自绘，鼠标仍按宿主的头像槽位操作。
- [ ] 接入 HUD 光栅缓存的部件 ID 或版本与主题／缩放变化，验证更换后下一帧出现正确部件。验证收发消息、同人消息分组、图片裁剪、头像缺失和 HUD 回退，内置外观通过既有像素回归。

### 3. 面板真实轮廓

- [ ] 由宿主管理面板边界及从附属取得的可重用轮廓。同一个结果用于 `PanelBackground` 的外框、阴影、背板、内裁剪，`AtomChatScreen` 的外部点击，以及 `PanelBlurRenderer` 和相关离屏合成的蒙版。所有三端使用一致的坐标和开合变换，轮廓变化触发相关缓存失效。
- [ ] 在样例提供明显切角的面板。对比可见边缘、世界模糊像素和实际点击结果，覆盖边角、开合动画、面板缩放、靠边布局和着色器开启。继续以既有 GPU 离屏路径作为生产入口。

### 4. 动态壁纸

- [ ] 在现有 `WallpaperStore`、`WallpaperImage` 和 `CardBackdrop` 入口增加受宿主管理的动态来源。每帧最多生成一次并复用于面板和卡片采样。壁纸实例随启用、停用、关闭或资源刷新释放；由宿主提供单调帧时间和当前画质。禁用动效时沿用静帧。
- [ ] 限制附属绘制到声明的边界。用独立记录画布或宿主隔离的同等机制保护后续 UI 绘制；执行失败回退到内置来源。注入的动画绘制不持有主帧缓冲。验证休眠、资源回收、多次启停和异常后的默认绘制。

## 验收

- [ ] 把一个独立 Java 示例作为普通 Mod 加载，分别选择四个部件，展示四个部件同时生效、可单独切回默认和重开保持。用两个附属 ID 验证混搭，保留 JEI 示例作为现有 Java API 的回归入口。
- [ ] 记录三个目标的构建、实际入口和原生像素结果。实机配对测量内置外观、静态附属和程序动画的面板冷开、静止、滚动及切页，核对三档画质。记录 GPU 蒙版更新开销，仅在有测量证据时报告帧时收益。
- [ ] 比较 AtomChat 和 AtomLib 的依赖边界。几何数据、绘制隔离和插件生命周期可作为复用候选；经独立消费者验证后再决定提取。聊天路由、服务器资源和玩家配置继续由 AtomChat 管理。
