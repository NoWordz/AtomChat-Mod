# AtomChat 0.5.0 面板掉帧：诊断、归因与修复方案

**目标：** 在无光影的真实场景中，找出面板常驻掉帧与切页长帧的主要成因；用可重复 A/B 证明修复效果，保留用户当前 UI 观感和交互。

**执行方式：** 接手 agent 自主实施诊断、验证、构建与证据整理；用户自行启动游戏并按脚本复现，agent 读取回传日志后继续归因、修复与复测。实机证据未取得时不得声称找到了根因或性能已改善。

**技术：** Java 17/21、Minecraft Forge 1.20.1 / Fabric 1.21.1 / NeoForge 1.21.1、AtomLib Skija bridge、OpenGL、JFR。先在用户实际反馈的 Fabric 1.21.1 环境定位，确认方案后覆盖三端。

- 用户指令为写方案供另一个 agent 实施；本方案不授权自动启动游戏、发布或推送。若使用既有获授权的测试实例部署，先记录现有文件、备份、替换并校验哈希；不干扰其他模组和配置。
- 先探后写：任何不熟悉的 JFR、LWJGL、OpenGL、构建或宿主 API，先用小探针验证真实签名、返回值和上下文要求，留源码或结果路径及行号。GPU query 的支持、分辨率、上下文及 GL 状态必须运行时验证，不能凭印象拼接口。
- 不用 `glFinish`、阻塞式 query 结果读取或每帧同步日志作为正常测量。保留 GL 状态和既有主帧缓冲 alpha 安全约束；不恢复有拖影的 `BlurMotionGate`；不以改变画质、去动画或移除效果冒充性能修复。
- 非平凡改动须独立 code-reviewer 复审；用户历史约定同时最多一个子代理。单测 → 全量套件 → 开发环境 smoke → 产物 smoke → 实机验收；缺失环节如实列出。

## 已知事实与不要误读的数字

- 现有 [采样状态](../../verification/2026-11-04-font-panel-blur-sampling.md) 已说明 `UiFrame`、`PanelSegments`、`Navigation`：前两者以非零面板帧号关联；导航发生在帧外时为 0，只能按时间对齐。这个编号**不是**完整游戏帧编号。
- 已有面板 `DRAW` 不含桥接状态保存、上下文准备、flush/submit、恢复及 GPU 完成；现有桥接前段/后段各是多个步骤的合计。屏幕构造、配置读写与首帧也未测。不能将独立分位数相减当作一帧内耗时。
- 旧实机日志中曾切换光影与背景模糊，滚动窗口混样；关闭光影、无 BLUR 的若干区间平均面板耗时约 5–8 ms。点阵混合窗口 p50 约 0.9–1.3 ms 是热点证据，**不是**已证实主因。旧交接文档关于每帧至少三处点阵存在互斥分支而高估，不能照搬。
- 游戏中的关面板基线、切页时逐帧归因、CPU 等待和 GPU 耗时均未确认。离屏 GPU query 探针只能证明本机一个上下文支持查询，不能证明游戏内相同。

## 任务 3：GPU 异步计时与帧时间对齐

- [ ] 小探针先查可用的 timer-query 扩展、对应 LWJGL 签名、实际 GL 上下文生命周期与 query 位宽；结果保存。设计有限 query 环形队列：帧 N 发起，后续帧仅在结果 available 时非阻塞读取；不可用、积压、溢出、上下文重建/销毁时跳过并计数、释放所有 query。不同 GL 扩展和 GPU/驱动不支持时继续 CPU 采样，不得影响绘制。
- [ ] 标明 query 作用范围：如只包面板 GPU 命令，只称面板 GPU 区间；渲染线程 CPU 时间不等于 GPU 完成时间。显式处理已有 query 冲突与 GL 状态恢复；不得用 `glFinish` 校准正式测量。时钟不同源时用可验证的帧/提交关联，不把 GPU query 当整个游戏帧时间。
- [ ] 测试 ready/未 ready、环满、丢弃/回收、异常、停用、重建；真实离屏 GL 测试验证正常渲染、结果延迟和清理，记录缺失数据占比与注入开销。只在用户实际游戏中复测后宣称游戏内可用。
