## 实施顺序

1. 输入根因：对照 `SettingsDetailPage.NumberEditInput` 与 `ServerConfigPage.key`、`SettingsFormField`。以最小行为回归验证普通输入不访问剪贴板、粘贴才访问；测量事件处理与布局，长文本变化才重新塑形。记录修改前后实测，不能将离屏计时说成GPU或实机掉帧修复。
2. 共用前端：核对 `SettingsSectionPage` 的分组几何/折叠/hover/press/ripple/滚动与 `PageTransitionComposite` 完整tab生命周期。将服务端页接入相同实际机制，必要时提取现有设置机制供两者调用，不另写近似实现。重点修改shared config/settings及三端AtomChatScreen宿主bodyVariant；合并卡片采用现有设置组卡的行高/间距规则，保留原信息结构。
3. 共用输入：`SettingsFormField` 与设置数字编辑共用框几何和单位布局。短文本居中；长文本按真实分行自适应1至4行，之后框内滚动；测量、文本、光标、选区、命中同源，支持中文/Unicode/粘贴/撤销/焦点。设置页仅数值框变更，不改变其其他动画或布局。
4. 行为及动态验证：普通输入/粘贴、1/2/4/5行、窄宽、中英、深浅主题、字段焦点/选择/光标、分组折叠/展开中间帧、tab离场/入场/快速反转/点击当前tab/滚动保持。沿用真实现有测试；关键缺陷用修改前失败的用例验证，不匹配源码字符串代替行为。
5. 候选：三端相关test/build、targets/JAR/bare和diffcheck；保留原基线WIP字节，不录宽容基线。生成同一候选、同一主题/宽度/内容的设置与服务端并排图及动态序列/可查看动图。真实完整前端合成链优先，不能继续只清纯色surface、手绘header、关闭动画冒充实际面板。离屏与实机界限必须标清，无法实测项明确列出。
