# AtomChat 0.7.1 UI 回归修复方案

目标：解释并修复 0.7.0 实测的材质、交互反馈、局部动画与布局问题，保留已认可的教程、HUD、点阵和编辑器行为。

## Grill 定案

- 默认布局保持图六的**实际外框**宽高比，尽量占满有边距的可用高度，窄视口等比适配。862 是已被视口裁切的配置值，不能作为比例依据。
- 宽高使用现有同一尺寸单位并显示 px；高度上下限随视口换算，不保留超过实际显示上限的无效滑条区间。高度下限约为自适应默认高度的 70%，窄视口同时考虑宽度约束。
- 已有布局保留；新安装及恢复外观/调整默认才采用新默认。编辑后仍允许宽高独立调整，半屏保留自身语义。
- 主面板描边选择更明显的明暗渐变与立体感。先定位图三已有异常亮带的来源；尊重描边颜色和宽度，不靠叠加白圈修复。
- 作者卡片与 UUID 卡片已有入场；只补缺失的悬停弹跳及适用的按压反馈，保留已有点击范围。
- 设置页内部 tab 切换复用现有全局 zoom/slide 语义，可连续打断；不另造动画系统。
- 悬浮窗及变体的有效按钮动作复用现有反馈音设置、音量及去重规则，鼠标与键盘一致。
- 0.6.0 仅作菜单族材质参照。按影响链修复，不整体回退。

## 本轮范围与顺序

1. [x] 菜单族材质：旧 JAR 字节码和旧 PNG 证实 fill→单层后叠阴影；仅恢复共享 MenuPopup 路径，覆盖表情/颜文字/表情包、快捷短语及各入口右键菜单，其他浮窗变体保留各自材质。
2. [x] 设置 tab：局部错峰原本存在；增加 bodyVariant，使局部 tab 变化触发现有全局 zoom/slide，真实绘制测试覆盖两次中断连续性。
3. [x] 浮窗反馈音：共用按钮 press 接入既有反馈音；颜色确认/取消在关闭开始触发；教程控制显式 press；鼠标及键盘批次复用既有去重，保留原音量开关。
4. [x] 描边与卡片阴影：渐变灯光限制在描边本身；列表显式水平 clip 预留共享阴影外扩，纵向边界保留；像素回归覆盖实际页面阴影与独立卡片对照。
5. [x] 面板编辑器文案：三端中英副文案移除换行控制字符，中文使用中点分隔，避免进入单行字形路径；已生成真实中文离屏图。
6. [x] 作者/UUID 卡片反馈：作者两张展示卡独立悬停缩放及颜色；UUID 整卡悬停与复制动作按压，点击范围保留。
7. [x] 响应式默认与高度范围：ScreenMetrics、滑条、编辑器取消、恢复默认、预设保存一致接入；宽高自动标记独立保存，修复独审发现的半屏应用手动高度被覆盖；定向测试覆盖新装/旧配置、720p/1080p/1440p/4K、超宽/窄视口、UI 缩放与半屏预设。
8. [x] 升版 0.7.1 与双语日志，集中独审及 P2 局部复核完成；三端串行 test build、成品/资源/targets/bare 通过，额外孪生台账扫描仍红并已披露。既有授权三实例备份部署与独立回读完成；未启动游戏、提交、推送或发布。详见 `docs/verification/2026-11-14-v071-ui-regressions.md`。

## 修改前的代码证据（定位依据，非实机验收结论）

- `MenuPopup.drawSurface` 在 20df2ab8 将旧 drawRoundedShadow 改为 SoftShadow.drawFloating；仍用 alpha 245 的固定面色。现有测试以同一绘制栈作期望，名为“保持渐变”却没有独立验证高光/透明层次。
- `PickerModalPaint.surface` 同时调用新增浮窗阴影和原阴影，需要核对叠加影响；不能直接等同于所有菜单的根因。
- `PanelBackground.drawBezel` 当前仅画纯色描边；上下栏另有 ChromeMaterial 的内侧光暗细节。截图的角部亮带仍须追踪实际叠层来源。
- 作者行被显式排除悬停与 PressScale；UUID 卡片 drawCard 的 hoverWeight 固定为 0。
- 面板编辑器 desc 包含换行，drawWrappedDescription 在宽度足够时直接走 drawText，存在控制字符进入单行字形路径的条件。
- ScreenMetrics 对高度取视口上限，而设置目录仍固定 600–1200，因此上限之后的配置值不再改变画面。

## 明确延期（用户要求只记录）

- **第 7 项，性能专项**：渲染掉帧、渲染优化、动画性能优化、非渲染性能优化。本轮不实施、不跑专项性能调优。
- **第 8 项，多人服务器偶发严重故障**：可能无法输入文字、无法发送图片、主题卡固定薄暮且不能切换、上下栏/内容全白或不渲染。用户自己的实例尚未复现；本轮只保存症状，不推断统一根因，不改网络/会话/渲染恢复链。

## 验证原则

- 先用现有行为/原生光栅测试复现缺陷，新增测试验证用户能看到的结果，不镜像当前实现。
- 只改相关源码及 official/Fabric 孪生；已有未修改且适用的验证记录可注明来源后复用。
- 视觉对照包含深浅底色、圆角、悬停/入场、阴影外扩与窄视口；不更新旧基线或放宽容差掩盖回归。
- 不建设 SHA 保护清单、trust 副本、hook、只读门禁或变异体系。
