# AtomChat 1.0.0 正式版后的扩展计划

## 0.9.8 收尾

- 「设置 → 外观与交互 → 预设」继续提供附属气泡和头像框选择。聊天面板与 HUD 共用选择，缺少 HUD 画法时使用内置样式。
- 隐藏尚未接入生产绘制的附属面板轮廓和动态壁纸选择。壁纸区显示实际生效的静态来源或无壁纸。保留注册方法及旧配置和预设的兼容读写。静态壁纸仍按原规则应用。
- 通过三端真实设置、消息面板和 HUD 检查候选包，备份并替换已授权的三个测试实例。公开发布与推送另行处理。

## 正式版后的顺序

1. **从真实改造需求开始。** 记录服主每次升级需要重复合并的改动，或作者已经在制作的美术。先确定一个要支持的效果和真实使用入口，再确定 API。界面、资源和后端能力按各自用例立项。
2. **以气泡预设验证卡片方案。** 有明确的创作需求时，让本体气泡和附属气泡共用预设条目。条目包含稳定 ID、实际画法和可选预览。没有指定美术时用生产画法生成预览，作者可提供自己的封面、构图或受裁剪的绘制。用现有港湾和信号验证默认预览与作者美术。AtomChat 继续管理横拖、点击、选中、保存和 HUD 回退。
3. **按需求扩到头像框、主题、壁纸和资源。** 已验证的卡片定义可以复用。纯美术优先走资源定义和资源重载，Java 留给程序绘制或自定义行为。主题预设可以引用不同作者的部件。面板轮廓与动态壁纸的生产接线按[外观 API 初期方案](2026-11-26-modular-appearance-api.md)各自的验收条件恢复排期，通过实测后再显示选择。
4. **交互、动画、动效和后端分别用真实场景验证。** 优先考虑可复用动作、页面内输入能力、动画配置、通知和消息事件、显式发送、只读查询及现有卡片门面。AtomChat 负责输入归属、动效打断、帧时钟、消息权限和协议。频道写入、管理写入、媒体访问等按对应服务端能力设计。

每次扩展都把公共定义放进三端共享源码，Official/Yarn 连接相同真实入口，并按 [UI 回归约定](../../UI_CONTRACT.md) 验证。优先验证附属与本体混用、缺失回退、重启保留、资源重载及实际入口。涉及绘制时记录冷开和切页帧时，缩略图按可见范围生成并复用。正式版之后也按实际需求决定范围。
