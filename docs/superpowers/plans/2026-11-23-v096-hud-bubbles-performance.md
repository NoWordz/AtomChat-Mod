# AtomChat 0.9.6 HUD、气泡与性能实施方案

目标：修复 GUI 缩放下的 HUD 长文本避让；实现紧凑消息单尖分组；提供三种气泡的真实原生渲染对照；静态分析图片上传消失；审计并优化渲染且保持其余观感；核对替换原版聊天 HUD 的兼容性。

基线：本地 main `6789b16b`，已发布 0.9.5。工作区 `atomchat-v096/AtomChat-Main`、分支 `codex/atomchat-v0.9.6`。旧目录实验改动保留。

## 已确认边界

- HUD 气泡右缘在原版快捷栏左缘前留间隙，按 GUI 缩放与实际可用宽度计算。低缩放显示更多内容；单行超宽使用省略号，面板保留完整内容。
- 兼容原版布局和只换外观的 HUD，移动或加宽快捷栏的第三方模组不在本版范围。
- 单尖同时用于面板和 HUD。紧凑消息分组是 Telegram 风格的前提，沿用现有同玩家连续发言与 5 分钟窗口。单条上尖、组首下尖、组尾上尖、中间无尖，使用本体尖角并左右镜像。
- HUD 保持现有全部靠左的布局，尖角跟随左侧头像；只有面板按发送方向左右镜像。用户指出中间气泡不能变成全圆胶囊，最终为靠头像侧上下小连接圆弧、远侧大圆弧。用户进一步明确单尖全部不受连续曲率影响，所有分组的填充、阴影及图片裁切使用显式普通圆弧。
- 另外两种气泡先提供实际渲染方案图，用户看过再决定是否落地。未经选择的造型留在预览源集。
- 指令或插件赋予名字的颜色和格式保留；无显式颜色时，面板使用 AC 配色、HUD 使用白色。
- 图片上传先静态分析潜在原因，不将无故障服证据的候选结论报告为确定根因。
- 性能先调研，保持阴影、AA、材质与动画；不将降低观感当作优化。未授权启动游戏、推送或发布；用户于11月24日明确授权本轮审核后本地提交0.9.6。

## 实施与证据

1. [x] **先调研与基线**：核对 Skia `saveLayer`、GPU 提交与资源缓存契约，阅读 Telegram 分组轮廓源码，只参考设计、不复制其实现；沿用固定 AtomLib 0.7.1 输入。复用已有原生测试和性能夹具，记录本轮命令与输出。
2. [x] **HUD 宽度与兼容**：修改 `shared/.../render/ChatHudRenderer.java` 的真实 Viewport 预算，必要时由三端 `ChatHudMixin` 传入原版副手占位信息；测试 GUI 各档、聊天缩放、窄窗口、长中英文、富文本、省略号和名字默认色。核对消息捕获、系统消息、装饰名、删除/屏蔽及原版回退路径。
3. [x] **单尖分组与原生预览**：在 `ChatBubble` 共用轮廓加入分组位置，接入 official 与 Fabric `MessageListView`、共享 `ChatHudRenderer`，覆盖文字、图片、加载/禁图占位、阴影和缓存。维持原布局与动效节奏。新增真实面板/HUD 渲染对照，展示单条、两条、三条、左右、普通/紧凑及另外两种的候选造型。用行为与像素回归验证，向用户展示原图。
4. [x] **上传静态分析**：追踪 picker/paste/drop 到 `ImageUploadPipeline`、托管媒体、外部图床、主线程回调、草稿目标、连接 epoch 与占位提示；按证据区分确定缺陷、可能环境原因和需要故障日志才能判断的分支，写明最小判别方法。
5. [x] **性能审计与优化**：对当前真实热路径定位重复布局、临时原生资源、重复提交、缓存失效和媒体工作；只保留有证据的优化。使用同场景配对量测和像素/状态对照，注明离屏、隐藏 GL 与完整游戏各自的覆盖范围。必要跨仓架构变化另行提出方案。
6. [x] **集中独审与验证**：整批后安排独立审查，核对五项需求、三端真实接线和证据，修正后增量复核；运行必要三端 test/build、既有契约及 targets/JAR/bare 检查。未通过或未覆盖的项如实列出，不刷新旧基线来掩盖回归。
7. [x] **交付与状态**：更新 0.9.6 版本和双语更新记录，逐项区分完成、已实现待验与限制。另外两种气泡保留待用户选择，不用单尖完成概括整单。

## 权威调研入口

- Skia Canvas：<https://api.skia.org/classSkCanvas.html>，`saveLayer` 创建额外表面；预算应覆盖真实绘制区域，不能当作免费状态保存。
- Skia GPU：<https://api.skia.org/classGrDirectContext.html>，外部 GL 状态与 context reset、flush/submit、缓存和资源寿命须遵守共享上下文契约。
- Telegram Desktop：<https://github.com/telegramdesktop/tdesktop/blob/dev/Telegram/SourceFiles/history/view/history_view_message.cpp>，研究分组边缘和到达动画；用户图二与口述规则是本次造型验收依据。
