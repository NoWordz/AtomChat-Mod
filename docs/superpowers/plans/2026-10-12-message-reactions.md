# 消息反应：0.3.0-Preview

> **实现期设计变更（2026-10-12）**：本文「实施结构与边界」一节描述的**签名指纹 + 服务端回执 + 原接收连接授权**模型在实机排查后被替换。原因：离线/局域网/插件服务器把玩家聊天作为无签名、无 MessageBody 的系统行交给客户端，客户端无法重算服务端指纹，反应入口在该类服务器上永不出现。
>
> 最终实现改为**内容键传输**：身份 = `SHA-256("content|author|body")`，两端各自从可见文本算出；服务端不观察投递、不校验身份，只在客户端提交的键下存储并广播，仅保留 emoji 白名单、限流与容量上限；作用域（私聊）靠「没有该行消息的客户端渲染不出 chip」天然成立——与引用气泡同一机制。下文关于指纹、回执、碰撞撤销、按接收连接广播、`MessageHandlerMixin` 投递前建身份的段落**已作废**，以 `docs/verification/2026-10-12-reactions.md` 为准。
>
> 另：本轮追加了 chip 入场/出场/计数脉冲动画与悬停名单渐隐渐显，见验证记录。

## 已确认的产品规则

- 服务端安装 AtomChat 才开放入口；安装了支持反应版本的原消息接收者可见，私聊仅原会话双方。
- 右键玩家气泡新增“添加反应”，复用仅显示标准 emoji 的选择面板。
- 气泡下方显示 emoji 和人数；点击切换自己的反应，自己的项高亮，悬停显示参与者。
- 每人每条最多 8 种，每条最多 20 种；单项最多 256 位参与者，服务端每个连接每秒最多 8 次操作。
- 客户端重连清空反应状态与绑定；历史重载的消息不开放入口。
- 防刷屏合并气泡代表最新一条；自己的合并气泡等待对应回声全部确认后开放，避免在最新发送尚未确认时操作旧消息。

## 实施结构与边界

`shared/reaction` 管消息指纹、服务器账本、客户端连接状态和有长度上限的协议。三端 `net/Reaction*` 仅负责各加载器的可选通道与线程切换。服务端 Mixin 放独立 common 配置，不加载客户端 AWT plugin；客户端 Mixin 在原生聊天实际投递 HUD 前建立身份上下文。

有签名消息用作者 UUID 与签名字节生成指纹。unsigned 消息使用作者、线上传输精度的毫秒时间、盐和原始正文；服务端发现不同原生消息碰撞时撤销两者授权并通知接收者。正文展示、引用解析、昵称猜测和各客户端行 ID 均不能给消息授予网络操作权限。

服务器只登记原生玩家聊天的实际接收连接；反应修改身份来自当前连接，不能由请求声称。账本最多保留 4096 条消息。重新连接的同一 UUID 不继承旧连接授权。广播只发原消息的原接收连接；无变化请求仅回复本人。系统公告、插件格式猜测、无法明确绑定的本地回声、旧历史不开放入口。

客户端状态最多保留 4096 条绑定、回执、快照和近期确认。跨私聊会话存在同正文待确认本地消息时保守关闭入口。断线清空客户端状态；仍在线的原接收者可继续看到当前服务器账本中的反应，返回者不能操作重载历史。

## 同轮静态审计修正

- `07e0a05` 抽取菜单时将“底色→阴影”对调为“阴影→底色”；恢复接受的内缘渐变，保留行弹跳，覆盖所有共用菜单。
- signed 私聊先按原生装饰组件分流，incoming 身份保留原生 UUID；官方映射捕获移到延迟回调实际投递时，避免单槽身份提前覆盖和私聊 echo 提前消费。
- 图片展示和保存的 HTTP 字节收集限制为 16 MiB；原始解码前限制 3200 万像素；失败 URL 缓存最多 512 条并淘汰过期项。
- 头像三端客户端复用预检与 256px 缩图；服务端用无需客户端/native 库的 PNG IHDR 检查拒绝巨大尺寸声明。
- 显示 metadata 尊重原生 FilterMask；未过滤时保留装饰富文本，部分过滤时使用原生格式化遮蔽结果。反应指纹仍独立使用签名/原始线上身份字段。
