# 2026-11-10

## 12:20-12:45 修 v0.6.0 的 AtomLib 依赖范围 bug，三端升 0.6.1 并发桌面

**现象（用户报）**：1.20.1 Forge 上装了 AtomLib 也提示缺依赖，任何版本的 AtomLib 都无法加载 AtomChat。

**根因（不是猜的，跑出来的）**：`gradle/atomchat-atomlib.gradle` 按加载器分叉了依赖范围串 —— Forge 用空字符串，凭的是「Forge 用空串表示任意版本」这句没核实过的注释。两端都把这串交给 Maven 的 `VersionRange.createFromVersionSpec()`，实机用 maven-artifact 3.9.1 跑出来的语义：

| spec | containsVersion(0.4.0) |
|---|---|
| `""` | **false**（restrictions 为空 → 一个都不匹配） |
| `"*"` | true |
| `"[0,)"` | true |

Forge 的 `ModSorter.verifyDependencyVersions` 只做 `depends.getVersionRange().containsVersion(installed)`，所以空串的后果是「装什么都不匹配」，报 `Missing or unsupported mandatory dependencies … Expected range: ''`。

**审计结论**：NeoForge 声明 `versionRange="*"`（同一 Maven 语义，健康）；Fabric 是 `suggests` + 启动期 `AtomLibDependencyCheck`（不卡版本，健康）。只有 Forge 这一处坏。

**改动**：
- `gradle/atomchat-atomlib.gradle`：范围一律取 `versions/atomlib.json` 的 `compatibility_range`，空值直接 GradleException（空串就是这个 bug 的形状）
- `tools/verify_jars.py`：期望值改读锁，三端同一个值；空范围判红
- `tools/test_verify_jars.py`：夹具跟锁值，新增「空范围三端都必须被拒」回归用例（18 tests OK）
- `mod_version` 0.6.0 → 0.6.1；CHANGELOG / RELEASE_NOTES 补段

**构建**：本地 AtomLib 输入用 `build/atomlib-input-0.4.0.zip`（sha256 与锁一致）解到 `build/maven-0.4.0`，三端 `clean build -PatomlibMavenRepo=...` 全绿，构建戳 `git_commit=68cd7cb git_dirty=false`。JDK：Forge 走 `C:\Program Files\Java\jdk-17.0.18`，Fabric/NeoForge 走 `C:\Program Files\Microsoft\jdk-21.0.8.9-hotspot`。

**交付**：三端 jar 放到桌面（`atomchat-Forge-1.20.1-v0.6.1.jar` / `atomchat-NeoForge-1.21.1-v0.6.1.jar` / `atomchat-Fabric-1.21.1-v0.6.1.jar`），sha256 见当次提交说明。
