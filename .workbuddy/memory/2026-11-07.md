
## 11-07 首开回归复查收尾（提交 `8f5a88ac`，已部署 CCB）

**背景**：用户 11-06 23:30 跑实例后报「稳态帧数比之前更低」。查下来**两次会话不可比**（地板被 400 帧锁截断；这次面板里有 851 次表情渲染而基线 0 次；`emotes_render`/`emoji_render`/`phrases_render` 三个桶是本次新增的埋点，不是新开销），所以 +1.24ms **无法归因**。但复查过程中挖出**两个我自己的真 bug**：

**bug ①：emoji 预热从来没跑过。** `prewarmEmojiAsync` 挂在 onJoin，而加入世界时聊天还是空的 → 列表空 → 直接 return。首开只能现场栅格化（`prewarm_emoji=-1.000`、`emoji_render max=159.32ms`）。**修法**：改成跟内容走——tick 里用 `ChatStore.generation()` 轮询，两秒节流，面板打开时不轮询，空 backlog 也记账。**教训：一次性事件不是内容的代理**。

**bug ②：模糊预热把容量下限抬高了。** `prewarm` 调 `ensureTextures(w,h,false)`（容量模式），而容量下限 `capW/capH` **只会变大不会变小**（正式路径取 `max(nextPow2(w), capW)`），预热按自己的面板尺寸抬了下限就再也降不回去；模糊 pass 跑整张容量纹理，于是每帧多付。真机 pre-pass **0.220 → 0.284ms**（passes 0.168 → 0.218）。**修法**：预热只编译 shader 不碰纹理；Forge/NeoForge 的 shader 本来就是启动期注册好的，预热直接 no-op。

**③ 可观测性**：`FirstOpenBudget` 新增 `first_draw` 段（首帧 render() 墙钟）。上一轮 `total=102.581ms` 里 `other=101.597ms` 没归因，最大嫌疑是 Skia 自己的管线编译（`prepare()` 只拿帧不画东西）。这轮只把它变可测。

**踩坑（今天第三次了，必须记牢）**：
- `prepare_snapshot.py` 里的 `copytree(..., dirs_exist_ok=True)` 用 `copy2`，**保留源文件 mtime** → 快照文件的 mtime 是源文件的时间，不是复制时间。别拿 mtime 判断快照新不新，要 grep 内容。
- 快照目录建在 `build/first-open-20261106/` 里面 → 跑完 gradle 后快照里会多出 `build/` 产物，触发脚本自己的「泄漏检查」误报。解法：泄漏检查排除快照自己的 build/。
- Forge/NeoForge 用**官方映射**：`client.screen`（不是 `currentScreen`）、`Window#getGuiScale()`；而且它们的 blur shader 是**启动期注册回调**拿到的，没有 `ensureLoaded()` 可调。
- JUnit 5 的消息参数在**最后**：`assertEquals(expected, actual, message)`，JUnit 4 的 `assertEquals(expected, actual, message1, message2)` 不存在。
- lambda 捕获的局部变量必须 effectively final：`specs = specs.subList(...)` 之后不能直接进 lambda，要 `final List<...> work = specs;`。
- **后台 Bash 任务会被沙箱拦**（`could not find /tmp`），前台跑就没事；三端构建要分三次前台跑（每端 <10 分钟）。
- `rm -rf` 批量删除（>50 文件）会被拦；删单个文件没问题。
